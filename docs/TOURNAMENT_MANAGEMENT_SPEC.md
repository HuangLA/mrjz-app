# 比赛管理系统方案

最后更新：2026-05-18

## 1. 定位

比赛管理系统是后端的核心业务域，负责把“一个 OpenDota 联赛里的比赛数据”组织成平台自己的赛事结构。它不只是赛程 CRUD，而是统一管理赛事、阶段、轮次、对阵、积分排名、淘汰赛晋级和 OpenDota match 关联。

小程序和 H5 不直接理解复杂赛制规则，只消费后端返回的统一展示模型。Web Admin 负责创建和维护赛制，后端负责计算和校验，管理员保留最终确认权。

## 1.1 2026-05-18 定稿边界

- 创建比赛和管理赛程是两个独立行为。创建比赛沿用现有流程：管理员填入 OpenDota `league_id` 后，系统自动同步这届联赛数据。
- 官方赛程管理是某届比赛下面的运营层，只影响 H5 的“赛程”页；比赛列表、比赛记录、比赛详情继续读取现有 OpenDota 数据。
- 每届比赛固定由一个预赛和一个淘汰赛组成。预赛为小组赛或瑞士轮；淘汰赛为单败或双败。
- 官方赛程有草稿、发布和撤回状态。未发布或撤回时，H5 赛程页显示“赛程暂未发布”。
- 参赛名单从当前届次已有队伍中勾选并锁定。确需修正时可解锁，但会清空官方赛程草稿。
- 操作日志先记录 `admin` / `system` 占位，后续接入管理员登录后写真实账号。

## 2. 设计原则

- 同一个赛季可以包含一个或多个赛事。
- 一个赛事可以包含多个阶段，例如小组赛、瑞士轮、淘汰赛。
- 所有赛制最终都落到 `series`，即一组 BO1/BO2/BO3 对阵。
- `series_games` 继续表达单局 Dota 2 match，并与 OpenDota `match_id` 关联。
- 排名、晋级和淘汰赛节点由后端根据赛果计算，但允许管理员手动修正并记录审计。
- 自动生成只作为“草稿辅助”，管理员发布后才对用户端可见。

## 3. 支持赛制

### 3.1 普通小组赛

适用：固定分组、每组内循环比赛。

能力：

- MVP 固定单循环，默认 BO2；后台不要求轮次，用户端按时间排序，时间允许待定。
- 支持管理员创建任意数量小组。
- 支持根据小组数量或每组队伍数随机分组；种子队尽量平均分散到不同小组。
- 支持管理员把当前赛事已有队伍手动加入任意小组。
- 支持后台拖拽队伍在小组间移动。
- 支持管理员手动创建、修改和删除小组赛对阵。
- 支持一键生成组内 BO2 单循环。
- 支持加赛 series。加赛只用于打破同分排序，不计入原积分。
- 支持小组内积分榜。
- MVP 积分规则：胜 3 分、平 1 分、负 0 分。
- 默认排名：管理员手动排序 > 积分 > 净胜局 > 胜场 > 队名。
- 支持每组前 N 名晋级到后续阶段。

用户端展示：

- 阶段 Tab：小组赛。
- 小组切换。
- 小组积分榜。
- 小组赛程和赛果。

### 3.2 瑞士轮

适用：队伍较多、不想完整循环、希望相近战绩队伍互相匹配。

能力：

- 配置总轮数。
- MVP 支持后端根据当前战绩生成下一轮配对草稿，管理员确认后发布。
- 管理员仍可按轮次手动创建、修改和删除配对。
- 对阵支持胜、负、平，战绩显示为 `胜-平-负`，例如 `1-2-1`。
- 后端配对默认同战绩优先并避免重复交手；无法完全避开时保留草稿给管理员调整。
- 支持奇数队伍轮空 BYE，轮空按一场胜利计入战绩。
- 支持按战绩分组配对，同分优先，必要时上下浮动。
- 支持管理员调整配对后发布。
- 支持瑞士轮战绩榜和晋级线。
- 支持异常处理：队伍退赛、轮空、弃权、补赛。

用户端展示：

- 阶段 Tab：瑞士轮。
- 当前轮对阵。
- 历史轮次。
- 瑞士轮积分榜。
- 晋级区/淘汰区提示。

### 3.3 淘汰赛

适用：单败淘汰、双败淘汰、决赛阶段。

MVP 支持：

- 单败淘汰。
- 4/8/16 队 bracket。
- 三四名决赛可选。
- 按种子位创建 bracket。
- 管理员可选择 4/8/16 支入围队伍并一键生成 bracket。
- 上一轮胜者由管理员点选确认后自动进入下一轮。
- 支持管理员手动替换参赛队、修正晋级结果。
- 双败淘汰草稿编排：创建胜者组、败者组和总决赛轮次。
- 双败首轮按种子生成 draft series；管理员选择胜者后，后端自动推进胜者组并把败者落入败者组。
- 管理员可在页面上查看实时 bracket，并直接选择每个节点胜者。

后续可扩展：

- 败者组复杂种子避让。
- 总决赛重置赛自动触发。

用户端展示：

- 阶段 Tab：淘汰赛。
- 移动端纵向 bracket。
- 每个节点显示 BO、比分、状态、match 关联状态。
- 已完成节点可进入比赛详情。

## 4. 核心对象

| 对象 | 说明 |
| --- | --- |
| `tournament` | 平台内的一次赛事，例如“每日节奏 S8” |
| `tournament_stage` | 赛事阶段，例如“小组赛 A/B 组”“瑞士轮”“淘汰赛” |
| `stage_team` | 阶段参赛队，可来自报名、上一阶段晋级或管理员手动加入 |
| `stage_group` | 小组赛分组 |
| `stage_round` | 阶段轮次，小组赛第 1 轮、瑞士轮第 3 轮、淘汰赛半决赛 |
| `series` | 一场 BO 对阵 |
| `series_game` | 一局 Dota 2 match |
| `stage_standing` | 阶段排名快照 |
| `bracket_node` | 淘汰赛节点 |

## 5. 后端职责

### 5.1 赛事配置

- 创建赛事。
- 绑定赛季和 OpenDota league_id。
- 创建阶段并选择阶段类型：`group`、`swiss`、`knockout`。
- 配置阶段顺序、可见性、晋级人数、积分规则和排名规则。

### 5.2 对阵创建

- 小组赛：管理员先创建小组并手动加入队伍，再手动创建、修改和删除 series。
- 瑞士轮：管理员配置总轮数，后端按当前胜平负生成下一轮配对草稿；管理员可确认、撤回、手动创建、修改和删除 series。
- 淘汰赛：按种子位生成 bracket 和首轮 series。
- 双败淘汰：按种子位生成胜者组首轮 series，并预建胜者组、败者组、总决赛和重置赛轮次草稿。
- 生成后处于 `draft` 状态，管理员确认后变为 `published`。

### 5.3 赛果与排名

- 管理员或 OpenDota 同步写入单局结果。
- 后端汇总 BO 胜负。
- 小组赛和瑞士轮在 series 赛果变更、删除或分组队伍变更后由后端重算阶段积分榜。
- 小组赛 MVP 使用胜 3 / 平 1 / 负 0；瑞士轮战绩显示胜-平-负。
- 瑞士轮每轮结束后可生成下一轮草稿。
- 淘汰赛节点完成后自动推进胜者。
- 所有自动计算结果允许管理员覆盖，覆盖必须写审计日志。

### 5.4 OpenDota 关联

- OpenDota 只提供真实 match 数据，不直接决定平台赛制结构。
- `match_id` 关联到 `series_games`。
- `schedule-linker` 关联成功后触发 series 赛果重算。
- 如果人工结果和 OpenDota 结果冲突，进入待确认队列，不自动推进排名或 bracket。

## 6. 状态流转

赛事状态：

- `draft`：后台配置中。
- `published`：用户端可见。
- `running`：已开始。
- `completed`：全部阶段结束。
- `archived`：历史赛事。

阶段状态：

- `draft`：阶段规则和队伍配置中。
- `published`：阶段赛程可见。
- `running`：已有比赛开始或完赛。
- `locked`：阶段结果锁定，用于生成下一阶段。
- `completed`：阶段结束。

Series 状态：

- `draft`：系统生成但未发布。
- `scheduled`：已发布，等待比赛。
- `live`：进行中。
- `result_pending`：等待赛果或 match_id。
- `completed`：赛果确认。
- `conflict`：人工结果和 OpenDota 冲突。
- `postponed`：延期。
- `cancelled`：取消。

## 7. 排名计算

基础字段：

- `series_played`
- `series_wins`
- `series_draws`
- `series_losses`
- `game_wins`
- `game_losses`
- `points`
- `opponent_score`
- `head_to_head_score`
- `manual_rank`

默认规则：

- 小组赛：积分 > 净胜局 > 胜场 > 直接交手 > 管理员手动排序。
- 瑞士轮：积分 > 对手分 > 净胜局 > 胜场 > 管理员手动排序。
- 淘汰赛：不使用积分榜，以 bracket 节点推进为准。

## 8. 前端展示协议

用户端统一使用阶段模型：

```json
{
  "tournament": {},
  "stages": [
    {
      "id": "stage_1",
      "type": "swiss",
      "name": "瑞士轮",
      "status": "running",
      "activeRound": {},
      "standings": [],
      "rounds": [],
      "bracket": null
    }
  ]
}
```

展示策略：

- 小程序和 H5 首页显示当前赛事、当前阶段、下一场、最新结果。
- 赛程页按阶段和轮次筛选。
- 小组赛显示小组积分榜。
- 瑞士轮显示总榜和每轮对阵。
- 淘汰赛显示 bracket。
- 比赛详情仍以 OpenDota match detail 为核心，但顶部显示所属赛事、阶段、轮次和 BO 信息。

## 9. 管理后台页面

新增或调整页面：

- 赛事管理：创建赛事、绑定赛季和 OpenDota league_id。
- 阶段管理：配置小组赛、瑞士轮、淘汰赛。
- 参赛队管理：报名队伍、阶段队伍、种子位。
- 小组赛管理：创建/修改/删除小组、手动加入/移除队伍、手动添加/修改/删除对阵和赛果。
- 瑞士轮管理：设置轮数、手动添加/修改/删除每轮对阵和赛果。
- 淘汰赛管理：选择入围队伍数量和队伍，一键生成单败或双败 bracket。
- 积分榜管理：查看自动排名、锁定阶段结果、手动调整排序。
- 晋级管理：从上一阶段选择晋级队伍进入下一阶段。
- Bracket 管理：查看淘汰赛节点、修正晋级、处理冲突。

## 10. 验收标准

- 管理员能创建一个含“小组赛 + 淘汰赛”的赛事。
- 管理员能创建一个含“瑞士轮 + 淘汰赛”的赛事。
- 管理员能手动创建小组、把已有队伍加入小组、手动创建对阵，并在填错时修改或删除。
- 小组赛能展示分组积分榜和每组赛程。
- 瑞士轮能按轮次展示对阵和总积分榜。
- 淘汰赛能展示 bracket，并在赛果确认后推进胜者。
- 后台能基于已有队伍创建双败淘汰赛草稿，并展示胜者组、败者组和总决赛对阵图。
- OpenDota match 同步后能关联到正确的 BO 单局。
- 赛果冲突不会直接污染排名或晋级结果。
- 小程序和 H5 使用同一 API 展示三种赛制。

## 11. MVP 边界

MVP 要做：

- 小组赛、瑞士轮、单败淘汰赛。
- 双败淘汰赛后台草稿编排和对阵图展示。
- 小组赛和瑞士轮采用管理员手动对阵管理，保留后续自动生成草稿扩展。
- 积分榜和 bracket 自动计算。
- 手动修正和审计日志。

MVP 暂不做：

- 完全无人值守自动赛程生成和发布。
- 双败淘汰完整自动推进和败者组落位。
- 复杂 Buchholz 变体和自定义瑞士轮算法插件。
- 自动判罚和自动处理争议。
