# 开发计划

最后更新：2026-05-13

## 1. 里程碑总览

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| M0 | 产品和技术定稿 | PRD、技术方案、页面参考、数据模型 |
| M1 | 工程骨架 | Taro 小程序、React Admin、手机 H5、Express API、数据库迁移、基础 CI |

## 4. M2：登录和权限

验收：

- 用户可以登录并看到自己的用户信息。

## 5. M3：赛事基础与管理后台

建议工期：7 到 10 天。

任务：

- 赛季管理。
- 联赛管理，配置 OpenDota league_id。
- 赛事管理：创建赛事、绑定赛季和 league_id。
- 阶段管理：支持普通小组赛、瑞士轮、淘汰赛。
- 参赛队和种子位管理。
- 小组赛分组、瑞士轮轮次、淘汰赛 bracket 的草稿生成和发布。
- 积分榜重算、阶段锁定和晋级确认。
- 自动同步配置：启停、同步频率、是否自动请求解析。
- 队伍管理。
- 选手管理和绑定审核。
- 赛程 CRUD。
- 单局赛果录入。
- 审计日志。
- Web Admin 工作台、列表页、表单页和详情页。

验收：

- 管理员能在 Web Admin 创建一场 BO3 赛程。
- 管理员能创建“小组赛 + 淘汰赛”和“瑞士轮 + 淘汰赛”两种赛事结构。
- 管理员能发布小组赛赛程草稿、瑞士轮配对草稿和淘汰赛 bracket 草稿。
- 后端能根据确认赛果重算积分榜或推进淘汰赛节点。
- 管理员能在 Web Admin 录入每一局比分和 match_id。
- 用户端能看到赛程列表和赛程详情。

## 6. M4：OpenDota 自动同步

建议工期：5 到 8 天。

任务：

- 封装 OpenDota Client。
- 接入 `/leagues/{league_id}/matchIds`。
- 接入 `/matches/{match_id}`。
- 接入 `/request/{match_id}` 和任务状态。
- 实现 `league-discovery` 定时任务，按 league_id 自动发现新比赛。
- 实现 `match-sync` 队列任务，自动拉取新 match_id 详情。
- 实现 `parse-request` 队列任务，对未解析比赛按策略自动请求解析。
- 实现 `parse-polling` 定时任务，自动刷新解析状态和高级数据。
- 实现 `schedule-linker`，尝试自动关联 Web Admin 赛程和 OpenDota match。
- 保存 `raw_match_json`。
- 结构化写入 `matches`、`match_players`、`match_drafts`、`match_chat`、`match_time_series`。
- Web Admin 自动同步配置页和同步任务状态页。
- 失败重试和错误记录。

验收：

- 管理员输入 league_id 并启用同步后，后端能按频率自动发现并同步新比赛。
- 输入 match_id 仍能手动同步单场比赛。
- 未解析比赛不会阻塞基础详情展示。
- 开启自动解析后，后端能自动请求 OpenDota 解析并刷新高级数据。
- 自动关联失败和赛果冲突会进入 Web Admin 待处理列表。
- 管理员可以在 Web Admin 看到同步进度和错误。

## 11. 风险优先级

P0：

- OpenDota 数据不完整导致比赛详情无法展示。
- 自动同步误关联赛程或重复同步比赛。
- 微信登录和用户绑定设计不清导致账号冒领。
- 管理员误录赛果没有审计和回滚。
- Web Admin 公网暴露后权限或密码策略薄弱。
- 标签被刷屏、刷赞或出现违规内容。
- H5 与小程序展示逻辑分叉，导致维护成本上升。

P1：

- 小程序长页面性能问题。
- H5 首屏资源过大，弱网访问慢。
- 图表组件包体积过大。
- 赛季、联赛、队伍、赛程之间关系设计不清。
- 小组赛、瑞士轮、淘汰赛规则混在赛程字段里，导致后续扩展困难。
- Web Admin 表单和小程序展示共用 API 时权限边界混乱。
- 标签云字号过大导致移动端布局混乱。

P2：

- 英雄和物品资源更新滞后。
- 复杂成就系统迁移成本高。

## 12. 建议开发顺序

1. 先打通 API、管理员登录、角色、赛季、赛事和阶段。
2. 再实现 TournamentService、赛程、赛果、积分榜和 bracket 的后端闭环。
3. 再打通 league_id 自动发现、match_id 同步和自动解析。
4. 再做 Web Admin 录入、自动同步配置和异常处理闭环。
5. 再做 H5 公开展示闭环，确保小程序审核前可分享。
6. 再做小程序比赛列表和详情基础版。
7. 最后增强图表、Ban/Pick、聊天、MVP。

这样可以尽早形成可用闭环：管理员在 Web Admin 配置 league_id、维护赛程和处理异常；后端自动发现并同步比赛；用户先通过 H5 查看赛程和战报，小程序审核通过后再承接登录互动体验。
