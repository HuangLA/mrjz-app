# 开发计划

最后更新：2026-05-13

## 1. 里程碑总览

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| M0 | 产品和技术定稿 | PRD、技术方案、页面参考、数据模型 |
| M1 | 工程骨架 | Taro 小程序、React Admin、Express API、数据库迁移、基础 CI |
| M2 | 登录和权限 | 微信登录、管理员登录、用户、角色、RBAC |
| M3 | 赛事基础与管理后台 | 赛季、联赛、队伍、选手、赛程 CRUD 的 Web Admin |
| M4 | OpenDota 同步 | league_id 同步、match_id 同步、解析请求、缓存 |
| M5 | 用户侧 MVP | 首页、赛程、比赛列表、比赛详情基础版、我的数据 |
| M6 | 比赛详情增强 | Ban/Pick、趋势图、分路、聊天、MVP、分享 |
| M7 | 上线准备 | 测试、真机适配、隐私合规、部署、微信审核 |

## 2. M0：文档阶段

状态：已开始。

任务：

- 建立 Git 仓库。
- 完成 PRD。
- 完成技术方案。
- 完成比赛详情参考分析。
- 完成开发计划。

验收：

- 文档能直接指导代码骨架搭建。
- 关键产品边界明确：本联赛数据、Web Admin 手动赛程赛果、OpenDota 补全数据、小程序只展示。

## 3. M1：工程骨架

建议工期：2 到 3 天。

任务：

- 初始化 monorepo。
- 创建 `apps/miniprogram` Taro + React + TypeScript。
- 创建 `apps/admin` React + Vite + TypeScript + Ant Design。
- 创建 `apps/api` Express + TypeScript。
- 创建 `packages/shared` 共享类型。
- 配置 ESLint、Prettier、TypeScript。
- 创建数据库迁移框架。
- 增加 `.env.example`。

验收：

- 小程序能启动到首页空壳。
- Web Admin 能启动到登录页空壳。
- API 有 `/health`。
- 数据库连接正常。
- 本地 README 可按步骤启动。

## 4. M2：登录和权限

建议工期：3 到 4 天。

任务：

- 小程序接入 `wx.login`。
- 后端接入 `code2Session`。
- 建立 `users`、`admin_users`、`user_roles`、`admin_roles`、`player_bindings`。
- 实现 token 生成、刷新和退出。
- 实现 RBAC 中间件。
- 实现 Web Admin 账号密码登录。
- 小程序不提供复杂管理入口，只保留必要展示能力。

验收：

- 用户可以登录并看到自己的用户信息。
- 非管理员访问管理 API 返回 403。
- 管理员可以登录 Web Admin。
- 管理员角色能由数据库种子数据初始化。

## 5. M3：赛事基础与管理后台

建议工期：5 到 7 天。

任务：

- 赛季管理。
- 联赛管理，配置 OpenDota league_id。
- 队伍管理。
- 选手管理和绑定审核。
- 赛程 CRUD。
- 单局赛果录入。
- 审计日志。
- Web Admin 工作台、列表页、表单页和详情页。

验收：

- 管理员能在 Web Admin 创建一场 BO3 赛程。
- 管理员能在 Web Admin 录入每一局比分和 match_id。
- 用户端能看到赛程列表和赛程详情。

## 6. M4：OpenDota 同步

建议工期：5 到 8 天。

任务：

- 封装 OpenDota Client。
- 接入 `/leagues/{league_id}/matchIds`。
- 接入 `/matches/{match_id}`。
- 接入 `/request/{match_id}` 和任务状态。
- 保存 `raw_match_json`。
- 结构化写入 `matches`、`match_players`、`match_drafts`、`match_chat`、`match_time_series`。
- Web Admin 同步任务状态页。
- 失败重试和错误记录。

验收：

- 输入 match_id 能同步单场比赛。
- 输入 league_id 能发现并同步新比赛。
- 未解析比赛不会阻塞基础详情展示。
- 管理员可以在 Web Admin 看到同步进度和错误。

## 7. M5：用户侧 MVP

## 11. 风险优先级

P0：

- OpenDota 数据不完整导致比赛详情无法展示。
- 微信登录和用户绑定设计不清导致账号冒领。
- 管理员误录赛果没有审计和回滚。
- Web Admin 公网暴露后权限或密码策略薄弱。

P1：

- 小程序长页面性能问题。
- 图表组件包体积过大。
- 赛季、联赛、队伍、赛程之间关系设计不清。
- Web Admin 表单和小程序展示共用 API 时权限边界混乱。

P2：

- 英雄和物品资源更新滞后。
- 复杂成就系统迁移成本高。

## 12. 建议开发顺序

1. 先打通 API、管理员登录、角色、赛季、赛程。
2. 再打通 match_id 单场同步。
3. 再做 Web Admin 录入闭环。
4. 再做小程序比赛列表和详情基础版。
5. 最后增强图表、Ban/Pick、聊天、MVP。

这样可以尽早形成可用闭环：管理员在 Web Admin 排赛、录结果、关联 match_id，用户在小程序查看赛程和战报。
