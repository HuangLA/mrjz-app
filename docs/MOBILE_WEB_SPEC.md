# 手机网页端 H5 方案

最后更新：2026-06-12

## 1. 定位

手机网页端是小程序上线延迟时的用户侧兜底入口，也是比赛分享链接的通用落地页。它不承担管理功能，主要覆盖公开展示和可分享体验。

优先目标：

- 小程序审核未通过或延迟时，用户仍能通过浏览器查看赛程和战报。
- 微信、QQ、微博、浏览器等环境里都能打开比赛详情。
- 后续小程序上线后，H5 仍作为分享、外链和搜索入口保留。

## 2. MVP 范围

MVP 必做：

- 首页。
- 赛事总览和阶段切换。
- 赛程列表和赛程详情。
- 小组赛积分榜、瑞士轮积分榜和淘汰赛 bracket 展示。
- 比赛记录列表。
- 比赛详情基础版。
- 选手主页和队伍主页；选手主页默认展示当前入口届次记录，往届参赛记录按届次折叠。
- 选手应援标签只读展示，仅展示已审核通过标签；标签按选手身份跨届展示；H5 不显示点赞数，只用同一选手内的点赞数相对倍率控制单行彩色文字大小，不同标签使用不同颜色，最小赞标签作为 `1x` 基准，最大可视倍率封顶 `20x`，超过封顶时做压缩但保留相对顺序；H5 可播放本地金色应援冲击波和固定小号 `❤️ +1` 快速渐隐反馈、弹开周围标签，但不写入点赞数。
- 分享链接和基础 SEO meta。

MVP 可选：

- H5 登录。
- 我的数据。

建议第一版 H5 先做公开展示，不把登录作为上线阻塞项。标签添加和真实点赞能力优先放到小程序端，H5 不提供标签写入入口；H5 点击标签只做本地视觉反馈，包括点击标签的高亮冲击波和周围标签弹开。

## 3. 技术建议

建议使用：

- React + TypeScript + Vite。
- 移动端 UI：自研轻量组件或 NutUI React。
- 图表：ECharts。
- 数据请求：TanStack Query + Axios。
- 部署：Nginx 静态站点。

目录：

```text
apps/mobile-web/
  src/
    pages/
    components/
    api/
    routes/
    styles/
```

可复用：

- `packages/shared` 中的接口类型、Dota 常量、格式化方法。
- 小程序端的页面信息架构和文案。
- 比赛详情的数据聚合 API。

## 4. 路由

```text
/                         首页
/tournaments/:id          赛事总览
/tournaments/:id/stages/:stageId  阶段页：小组赛、瑞士轮、淘汰赛
/schedules                赛程
/schedules/:id            赛程详情
/matches                  比赛记录
/matches/:matchId         比赛详情
/players/:id              选手主页
/teams/:id                队伍主页
```

## 5. 与小程序的关系

- API 完全共用。
- 页面结构尽量一致，但 H5 允许使用浏览器能力，例如链接分享、meta 标签、复制链接。
- 小程序上线后，H5 页面可增加“打开小程序”入口。
- 小程序不可用时，H5 是默认传播入口。
- 小组赛、瑞士轮和淘汰赛都由后端返回统一阶段模型，H5 不自行计算排名和晋级。
- 阶段页同步显示后端 standings、管理员录入的轮次赛程，以及淘汰赛 bracket 节点。
- 淘汰赛 bracket 节点按后端返回的组别展示：单败为单一淘汰赛泳道，双败按胜者组 / 败者组 / 总决赛分区，并标注胜者和负者流向。
- 小组赛积分按后端返回的胜 3 / 平 1 / 负 0 展示；瑞士轮战绩按 `胜-平-负` 展示，例如 `1-2-1`。
- 官方赛程管理只影响 H5 的“赛程”页。未发布或撤回时，赛程页显示“赛程暂未发布”；比赛列表、比赛记录和比赛详情不受影响。
- 小组赛加赛在赛程卡片中标注为“加赛”，但排名和晋级仍以后端返回的 standings 为准。

## 6. 部署

推荐域名：

```text
m.example.com          # 手机网页端
api.example.com/api    # 后端 API
```

最低要求：

- HTTPS。
- 移动端首屏加载尽量小于 2 秒。
- 静态资源开启缓存。
- 重要页面配置 Open Graph / 微信分享 meta。
