# Web 管理后台方案

最后更新：2026-05-18

## 1. 定位

Web Admin 是赛事运营人员的数据控制台。它承担所有复杂写操作：赛季、赛事、阶段、队伍、选手、赛程、赛果、match_id、OpenDota 同步和权限管理。微信小程序和手机网页 H5 只展示公开赛事数据、用户个人数据和必要互动，不承载复杂后台表单。

这个切分更适合实际运营：管理员在电脑上处理表格、筛选和批量录入，小程序和 H5 保持轻量、稳定、容易发布。

## 2. 技术建议

- React + TypeScript + Vite
- Ant Design
- React Router
- TanStack Query + Axios
- 独立构建为静态资源，由 Nginx 部署

目录：

```text
apps/admin/
  src/
    pages/
    components/
    layouts/
    api/
    hooks/
    routes/
```

## 3. 权限

角色：

- `team_admin`：维护本队资料、成员和提交本队比赛 match_id。
- `tournament_admin`：维护赛季、队伍、选手、赛程、赛果、同步任务。
- `super_admin`：管理管理员账号、角色、系统配置。

MVP 使用账号密码登录：

- 超级管理员通过 seed 初始化。
- 密码只保存哈希。
- 登录态与小程序 token 分离。
- 后续可加二次验证或微信扫码登录。

## 4. 页面

### 4.1 登录页

功能：

- 用户名、密码登录。
- 登录失败提示。
- 记住登录状态，默认短有效期。

验收：

- 非管理员无法登录。
- 登录失败不暴露账号是否存在。

### 4.2 工作台

功能：

- 当前赛季概览。
- 待补录赛果。
- 同步失败任务。
- 近期赛程。
- 最近同步记录。

验收：

- 管理员进入后能立刻知道今天该处理什么。

### 4.3 赛季与联赛

功能：

- 创建、编辑、启停赛季。
- 配置 OpenDota league_id。
- 配置自动同步频率和是否自动请求 OpenDota 解析。
- 设置默认展示赛季。

验收：

- 同一时间只能有一个默认赛季。
- league_id 修改需要二次确认。
- 启用自动同步后，后端会按频率自动发现新比赛，管理员只处理异常和纠偏。

### 4.4 赛事与阶段管理

功能：

- 创建赛事，绑定赛季和 OpenDota league_id。
- 创建阶段并选择赛制：普通小组赛、瑞士轮、淘汰赛。
- 配置阶段顺序、展示状态、BO 类型、晋级名额和排名规则。
- 配置阶段参赛队、种子位和上一阶段晋级来源。
- 小组赛：创建任意数量分组、手动维护组内队伍、手动添加/修改/删除组内对阵和结果。
- 瑞士轮：配置总轮数，手动添加/修改/删除每轮配对和结果；战绩按胜-平-负展示。
- 淘汰赛：选择 4/8/16 支入围队伍，一键生成单败或双败 bracket；管理员在对阵图节点上只需选择胜者，后端负责推进胜者并处理双败败者组落位。
- 发布阶段和草稿对阵。
- 锁定阶段结果，用于生成下一阶段参赛队。

验收：

- 管理员能创建“小组赛 + 淘汰赛”的赛事。
- 管理员能创建“瑞士轮 + 淘汰赛”的赛事。
- 管理员能在填错队伍、比分或轮次时直接修改或删除 series。
- 管理员能基于已有队伍创建双败淘汰赛草稿，并查看胜者组、败者组和总决赛对阵图。
- 所有自动生成的对阵发布前都是草稿。
- 阶段结果锁定后，如需修改必须二次确认并记录审计日志。

### 4.5 队伍管理

功能：

- 队伍列表、搜索、筛选。
- 创建和编辑队伍名、简称、Logo、颜色。
- 管理队伍成员：支持在队伍提前建立、数据库尚无选手档案时，通过 SteamID64 或 Dota account_id 添加成员。
- 添加成员后，后端自动尝试从 Steam / OpenDota 补齐选手昵称和头像；管理员仍可手动维护队伍 Logo、颜色等资料，手动资料和自动资料共存。
- 支持从队伍移除成员，但不删除选手档案。

验收：

- 队伍名和简称在同赛季内不能重复。

### 4.6 选手管理

功能：

- 创建和编辑选手。
- 维护 Dota 2 account_id、steam_id64、展示昵称、头像。
- 审核用户绑定申请。

验收：

- 同一个 Dota 2 account_id 不能绑定多个选手。
- 绑定审核必须记录操作者。

### 4.7 赛程管理

功能：

- 在某届比赛下直接进入官方赛程管理，不需要单独“启用”按钮。
- 顶部展示官方赛程状态：未配置、草稿、已发布、已撤回，以及名单锁定状态。
- 从当前届次已有队伍中勾选参赛名单并锁定；解锁名单需要二次确认，并清空官方赛程草稿。
- 选择预赛赛制：小组赛或瑞士轮。
- 选择淘汰赛赛制：单败或双败。
- 发布前展示检查项：名单是否锁定、预赛/淘汰赛赛制是否选择、是否存在官方赛程阶段。
- 支持发布和撤回官方赛程；撤回后 H5 赛程页显示“赛程暂未发布”。
- 操作日志只在 Admin 展示，MVP 先记录占位操作者。
- 赛程列表：赛事、赛季、阶段、轮次、队伍、状态筛选。
- 创建 BO1、BO2、BO3 等 series。
- 设置计划时间、双方队伍、备注、所属阶段和轮次。
- 支持为小组赛 series 指定所属小组。
- 修改状态：未开始、已确认、进行中、待补录、已完赛、延期、取消。
- 支持删除错误 series。
- 展示来源：手动创建、小组赛生成、瑞士轮生成、淘汰赛 bracket 生成。

验收：

- 已完赛但没有 match_id 的比赛可以显示人工赛果。
- 延期和取消必须填写原因。

### 4.8 赛果录入

功能：

- 为每一局录入比分、胜方、match_id。
- MVP 支持直接录入 series 总比分；小组赛和瑞士轮允许平局。
- 检测 OpenDota 返回结果与人工结果是否冲突。
- 允许解绑错误 match_id 并重新关联。
- 赛果确认后触发阶段积分榜重算或淘汰赛晋级。

验收：

- 重复 match_id 不允许保存。
- 人工胜方与 OpenDota 胜方冲突时进入“待确认”。
- 冲突状态下不自动推进排名或 bracket。

### 4.9 积分榜与 Bracket 管理

功能：

- 查看小组赛积分榜。
- 查看瑞士轮积分榜、轮次和 BYE。
- 查看单败或双败淘汰赛 bracket。
- 小组赛 MVP 使用胜 3 分、平 1 分、负 0 分。
- 手动重算积分榜。
- 手动修正排名、晋级队伍或 bracket 节点。
- 填写手动修正原因。

验收：

- 排名修正必须进入审计日志。
- 用户端只展示已确认或已发布的排名和 bracket。

### 4.10 数据同步

功能：

- 查看 league_id 自动同步配置和最近执行时间。
- 查看后端自动发现的新比赛。
- 查看自动解析请求状态。
- 按 match_id 手动同步单场比赛。
- 按 league_id 手动触发一次发现任务。
- 手动请求 OpenDota 解析。
- 查看同步进度、失败原因、重试。
- 处理赛程自动关联失败和赛果冲突。

验收：

- 同步任务可追踪状态。
- 外部接口失败不会影响用户侧已有缓存数据。
- 管理员无需手动维护所有 match_id，只有自动关联失败时才需要介入。

### 4.11 互动标签管理

功能：

- 查看选手标签和队伍标签。
- 按目标类型、目标名称、创建用户、点赞数、状态筛选。
- 隐藏违规标签、恢复误隐藏标签。
- 查看标签创建人、创建时间、点赞数和举报记录。

验收：

- 隐藏标签需要填写原因。
- 普通用户无法看到已隐藏标签。
- 标签隐藏、恢复都必须进入审计日志。

### 4.12 权限与审计

功能：

- 管理管理员账号。
- 分配角色和作用范围。
- 查看审计日志。

验收：

- 所有写操作必须记录旧值、新值、操作者和时间。
- 超级管理员不能删除自己的最后一个超级管理员权限。

## 5. 部署

推荐部署到云服务器：

```text
admin.example.com    -> Nginx 静态站点
api.example.com/api  -> Nginx 反向代理到 Express API
```

最低要求：

- HTTPS。
- 管理后台域名不配置到小程序，只给管理员使用。
- API 域名配置到小程序 request 合法域名，并允许 H5 域名跨域访问。
- 数据库每日备份。
- 日志保留至少 14 天。
