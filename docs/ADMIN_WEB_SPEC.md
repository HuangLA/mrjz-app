# Web 管理后台方案

最后更新：2026-06-06

## 1. 定位

Web Admin 是赛事运营人员的数据控制台。它承担所有复杂写操作：赛季、赛事、阶段、队伍、选手、赛程、赛果、match_id、OpenDota 同步和权限管理。微信小程序和手机网页 H5 只展示公开赛事数据、用户个人数据和必要互动，不承载复杂后台表单。

这个切分更适合实际运营：管理员在电脑上处理表格、筛选和批量录入，小程序和 H5 保持轻量、稳定、容易发布。

## 2. 技术建议

- React + TypeScript + Vite
- Ant Design
- React Router
- TanStack Query + Axios
- 独立构建为静态资源，由 Nginx 部署

目录：

```text
apps/admin/
  src/
    pages/
    components/
    layouts/
    api/
    hooks/
    routes/
```

## 3. 权限

角色：

- `team_admin`：维护本队资料、成员和提交本队比赛 match_id。
- `tournament_admin`：维护赛季、队伍、选手、赛程、赛果、同步任务。
- `super_admin`：管理管理员账号、角色、系统配置。

MVP 使用账号密码登录：

- 超级管理员通过 seed 初始化。
- 密码只保存哈希。
- 登录态与小程序 token 分离。
- 后续可加二次验证或微信扫码登录。

## 4. 页面

### 4.1 登录页

功能：

- 用户名、密码登录。
- 登录失败提示。
- 记住登录状态，默认短有效期。

验收：

- 非管理员无法登录。
- 登录失败不暴露账号是否存在。

### 4.2 工作台

功能：

- 当前赛季概览。
- 待补录赛果。
- 同步失败任务。
- 近期赛程。
- 最近同步记录。

验收：

- 管理员进入后能立刻知道今天该处理什么。

### 4.3 赛季与联赛

功能：

- 后台必须保留创建大联赛 / 届次入口：管理员填写赛事名称和 OpenDota `league_id` 后即可创建新的平台赛事。
- 创建、编辑、启停赛季。
- 配置 OpenDota league_id。
- 配置自动同步频率和是否自动请求 OpenDota 解析。
- 设置默认展示赛季。

验收：

- 同一时间只能有一个默认赛季。
- league_id 修改需要二次确认。
- 启用自动同步后，后端会按频率自动发现新比赛，管理员只处理异常和纠偏。

### 4.4 赛事与阶段管理

功能：

- 创建赛事和管理官方赛程是两个独立动作；桌面端创建赛事入口必须明确标注为“添加联赛 / 新建大联赛 / 届次”，同时出现在当前届次选择附近和后台顶部操作区，点击后在主工作区顶部展开创建表单，阶段赛程只负责该届次下的小组赛 / 瑞士轮 / 淘汰赛编排。
- 在窄屏或内置浏览器里，当前届次选择附近的“添加联赛”入口也必须保留为紧凑按钮，不能只剩顶部操作区入口。
- 当数据库暂无任何届次时，后台需要自动展开大联赛创建表单并聚焦联赛名称输入框；创建成功后自动切换到新届次，并触发一次 OpenDota 比赛记录拉取。
- 大联赛创建表单的提交按钮必须明确写出“创建大联赛并同步”，避免管理员把它误解成当前届次里的赛程阶段创建。
- 管理员切换后台主功能页时，需要自动收起未提交的大联赛创建表单；表单状态可以保留，避免它继续压住战队、比赛结果库或同步任务工作区。
- 创建赛事，绑定赛季和 OpenDota league_id。
- 创建阶段并选择赛制：普通小组赛、瑞士轮、淘汰赛。
- 配置阶段顺序、展示状态、BO 类型、晋级名额和排名规则。
- 配置阶段参赛队、种子位和上一阶段晋级来源。
- 小组赛：创建任意数量分组、手动维护组内队伍、手动添加/修改/删除组内对阵和结果。
- 瑞士轮：配置总轮数，手动添加/修改/删除每轮配对和结果；战绩按胜-平-负展示。
- 瑞士轮主画布提供手动配对拖拽板，管理员可按当前战绩队伍池拖两支队伍补一场 BO2 配对。
- 瑞士轮主画布在第一轮未生成时必须直接展示“自动配对草稿”主入口；手动拖拽配对仍保留在同一工作台。已有轮次后，自动生成下一轮草稿可收进“自动配对辅助”抽屉，避免覆盖当前赛果维护。
- 小组赛 / 瑞士轮手动排赛板在已有推荐下一场时，默认动作必须先把推荐队伍放入左侧 / 右侧，跳过检查写入推荐草稿只能作为次级快捷动作且需要二次确认；这样默认路径仍然是拖拽 / 检查 / 确认。
- 小组赛 / 瑞士轮手动排赛板需要以左侧 / 右侧投放位作为第一操作面，队伍池作为来源区排在投放位之后；窄屏下也要保持投放位优先可见，避免管理员先扫一长串队伍却找不到拖拽目标。
- 小组赛 / 瑞士轮手动排赛板的左侧 / 右侧投放位需要组成一个明确的“对阵投放区”，中间用稳定的 VS 连接，避免两个独立框让管理员额外理解这是同一场 BO2。
- 小组赛 / 瑞士轮手动排赛板的空槽和推荐槽必须使用“左 / 右”侧位标记，不使用 `1 / 2` 这类容易被误解成排名、种子或场序的数字。
- 小组赛 / 瑞士轮手动排赛板在窄屏可创建态必须优先展示完整队名和确认动作，BO 类型、积分规则和进度标签不得挤占队名确认空间。
- 淘汰赛：预赛结果确定后选择 4/6/8/16 支入围队伍生成单败对阵图，或选择 4/8/16 支生成双败对阵图；管理员在对阵图节点上只需选择胜者，后端负责推进胜者并处理双败败者组落位。
- 预赛主画布提供“从预赛排名生成淘汰赛”拖拽区，管理员可直接从当前排名拖入晋级队伍并生成对阵图。
- 小组赛预赛已有排名后，淘汰赛入围区需要提供按小组名次的快捷入围，例如两组前三直接生成 6 队单败入围顺序：两个小组第一作为 1/2 种子等待半决赛，第二 / 三名进入第一轮；快捷入围后仍允许拖拽调整种子。
- 当“小组名次快捷入围”可用时，它必须作为唯一推荐填充动作展示，通用“按排名填满”只在没有该推荐时出现，避免管理员同时看到两个语义接近的自动入口。
- 当“小组名次快捷入围”可用且入围区为空时，顶部生成命令的主按钮必须先变为“填入推荐 N 队”；填入后再变为“生成 N 队单败对阵图”，不能让管理员在默认规模的“还差 N 队”和下方推荐条之间来回判断。
- 当“小组名次快捷入围”可用且尚未选择入围队伍时，淘汰赛入口状态和入围区标题必须显示推荐目标人数，例如“推荐 6 队入围”，不能继续用当前手动规模造成“0/4 与 6 队推荐”并存的误解。
- 淘汰赛生成命令必须直接显示当前会生成的对阵图类型和入围进度，例如“生成 6 队单败对阵图”或“还差 2 队”；6 队单败的“前 2 种子半决赛等待、3 vs 6、4 vs 5”结构说明要在入口处直接可见，不能只藏在预览抽屉里。
- 淘汰赛入围拖拽、种子预览和生成按钮只保留在预赛主画布；右侧 inspector 不再提供重复的淘汰赛生成表单。
- 淘汰赛入围拖拽区必须目标优先：先显示“淘汰赛入围槽位”和下一槽位说明，再显示预赛排名 / 可选队伍候选池，避免管理员先看到候选队伍却不知道拖到哪里。
- 淘汰赛对阵图主画布需要提示第一个待处理动作：补槽位、选择胜者或等待上游结果；槽位队伍可拖回待落位池取消落位，也可拖到其他槽位互换。
- 淘汰赛对阵图生成成功后，Admin 必须自动切到新淘汰赛阶段并定位第一个当前动作，直接进入拖拽补位或判胜工作台。
- 淘汰赛阶段已生成后，预赛主画布的淘汰赛入口和右侧淘汰赛管理提示都必须提供“打开对阵图”主动作，直接切到淘汰赛阶段并自动定位当前第一个待补槽 / 待判胜节点，不能只提示管理员去找阶段 Tab。
- 发布阶段和草稿对阵。
- 锁定阶段结果，用于生成下一阶段参赛队。

验收：

- 管理员能创建“小组赛 + 淘汰赛”的赛事。
- 管理员能创建“瑞士轮 + 淘汰赛”的赛事。
- 管理员能在填错队伍、比分或轮次时直接修改或删除 series。
- 管理员能基于已有队伍创建双败淘汰赛草稿，并查看胜者组、败者组和总决赛对阵图。
- 所有自动生成的对阵发布前都是草稿。
- 阶段结果锁定后，如需修改必须二次确认并记录审计日志。

### 4.5 队伍管理

功能：

- 队伍列表、搜索、筛选。
- 创建和编辑队伍名、简称、Logo、颜色。
- 管理队伍成员：支持在队伍提前建立、数据库尚无选手档案时，通过 SteamID64 或 Dota account_id 添加成员。
- 添加成员后，后端自动尝试从 Steam / OpenDota 补齐选手昵称和头像；管理员仍可手动维护队伍 Logo、颜色等资料，手动资料和自动资料共存。
- 添加成员按钮必须明确写成“添加并同步”或等价文案，提示管理员输入 SteamID 后会触发资料补齐；成员移除图标按钮必须包含队伍和成员名称的 `aria-label`。
- 队伍卡片默认应优先展示 SteamID 添加和成员列表；队名、简称、Logo、颜色和 OpenDota ID 等资料维护收进可展开“资料编辑”区，关闭态不挂载内部输入，避免批量加删人员时被表单淹没。
- 支持从队伍移除成员，但不删除选手档案。

验收：

- 队伍名和简称在同赛季内不能重复。

### 4.6 选手管理

功能：

- 创建和编辑选手。
- 维护 Dota 2 account_id、steam_id64、展示昵称、头像。
- 审核用户绑定申请。

验收：

- 同一个 Dota 2 account_id 不能绑定多个选手。
- 绑定审核必须记录操作者。

### 4.7 赛程管理

功能：

- 在某届比赛下直接进入官方赛程管理，不需要单独“启用”按钮。
- 顶部展示官方赛程状态：未配置、草稿、已发布、已撤回，以及名单锁定状态。
- 从当前届次已有队伍中勾选参赛名单并锁定；解锁名单需要二次确认，并清空官方赛程草稿。
- 提供“重置官方赛程”危险操作：允许删除当前届次已锁参赛名单、赛制配置、官方阶段、分组、对阵、赛果、淘汰赛对阵图和发布状态，但不得删除 OpenDota 拉取的比赛记录或比赛详情。
- 参赛名单锁定的写入动作只保留在官方赛程控制台的拖拽名单区；空阶段画布和步骤卡只定位到名单区。
- 参赛名单拖拽池支持按队伍全名、缩写、种子或状态搜索，并允许把当前筛选结果一键加入名单；筛选和批量加入只影响锁定前草稿。
- 当前届次暂无队伍时，参赛名单拖拽池必须明确显示“暂无队伍 / 先同步或创建队伍”方向，不能显示“所有队伍都已加入名单”；搜索无结果和已全部加入也要分别展示不同空态。
- 参赛名单未锁定时必须以紧凑命令栏作为名单区首屏：集中展示当前名单状态、搜索、批量加入、清空和唯一锁定按钮；当前届次队伍、参赛名单、种子队拖拽区紧随其后。
- 参赛名单锁定后默认只显示队伍数量、种子数量和少量队伍预览；完整名单放入可展开明细，避免控制台挤占后续赛程操作。
- 小组赛预赛草稿创建前，管理员可以拖拽手动预分组，也可以点击随机预分组；随机预分组必须尽量均衡分配到当前选择的小组数量，且只影响未发布草稿。
- 选择预赛赛制：小组赛或瑞士轮。
- 选择淘汰赛赛制：单败或双败。
- 赛制选择区提供常用模板快捷入口，例如“小组 + 单败”“瑞士轮 + 单败”“小组 + 双败”；模板只同步当前选择，仍需管理员点击保存后才驱动创建入口。
- 赛制选择区未保存或需要调整时，首屏必须使用紧凑命令栏集中展示当前状态、常用模板和唯一保存按钮；小组赛 / 瑞士轮、单败 / 双败的逐项选择放入可展开精确调整区。
- 赛制选择区必须同时显示“已保存方案”和“正在选择方案”；存在未保存修改时，需要提示下方预赛创建入口仍按已保存方案工作。
- 赛制已保存且没有未保存修改时，控制台默认只显示赛制摘要；模板和详细选择放入可展开编辑器，避免基础配置长期挤占阶段编排区域。
- 已创建预赛阶段后不允许直接切换小组赛 / 瑞士轮；已创建淘汰赛阶段后不允许直接切换单败 / 双败，需要先重置官方赛程再重建。
- 发布前展示检查项：名单是否锁定、预赛 / 淘汰赛赛制是否选择、是否存在预赛阶段、预赛是否已有可展示对阵；淘汰赛可在预赛结果确定后再生成。
- 发布前展示 H5 可见性和发布影响摘要，说明当前 H5 是否仍显示未发布、预赛阶段是否已创建、淘汰赛是否稍后生成。
- 已进入具体官方阶段后，即使基础设置默认收起，关闭态也必须展示 H5 可见性，例如“H5 未发布 / 已撤回”或“H5 可见”，避免管理员排完赛后忘记发布。
- 顶部官方阶段状态条不得把未生成淘汰赛显示成阻塞性的“缺淘汰赛”；预赛未排赛时显示“淘汰赛等预赛”，预赛已有对阵但尚未生成淘汰赛时显示“淘汰赛可稍后”。
- 发布检查区默认使用紧凑命令栏展示“是否可发布 / 还差几项 / H5 当前影响 / 发布按钮 / 重置官方赛程”；完整检查项继续放入可展开明细，避免发布信息长期挤占编排区域。
- 左侧赛事搭建流程按“参赛名单 -> 赛制选择 -> 预赛阶段 -> 淘汰赛（可稍后）-> 发布”展示；淘汰赛缺失但预赛已可发布时标为可稍后，不阻塞发布入口。
- 支持发布和撤回官方赛程；撤回后 H5 赛程页显示“赛程暂未发布”。
- 操作日志只在 Admin 展示，MVP 先记录占位操作者。
- 赛程列表：赛事、赛季、阶段、轮次、队伍、状态筛选。
- 已有对阵的官方阶段主画布顶部需要显示赛果处理入口：集中展示赛果完成度、Dota2 match_id 关联进度，并按下一条待办显示“定位待赛果”或“定位缺 ID”和“打开赛程列表”，避免创建对阵后继续向下翻找。
- 手动创建小组赛 / 瑞士轮对阵成功后，页面需要清空赛程列表筛选并优先自动定位 / 高亮刚创建的 series 行；后端没有返回 id 时才退回阶段赛程列表，方便管理员马上补赛果、补 match_id 或修正对阵。
- 手动创建对阵后，阶段顶部赛果处理入口的刚创建动作必须按该行状态显示：未录比分时显示“补刚创建赛果”并切到待赛果筛选，比分已录但缺单局 ID 时显示“补刚创建 ID”并切到缺 ID 筛选，全部完成后才显示“查看刚创建”。
- 阶段顶部“赛果处理”快捷条定位刚创建或待处理对阵时，必须同步清空赛程列表搜索、切换到能显示目标行的筛选，再聚焦目标行；目标行不存在时退回赛程列表本身，不能出现按钮点了但列表仍被旧筛选隐藏的情况。
- 阶段赛程列表默认使用赛果处理命令栏：集中展示已录赛果、待补赛果、Dota2 match_id 关联进度、搜索和明确的定位动作；下一条待办是比分时显示“定位待赛果”，比分已齐但缺 ID 时显示“定位缺 ID”，避免管理员从长列表里肉眼找未处理项。
- 顶部“下一步”和阶段内“赛果”快捷入口在已有对阵时必须直接定位第一条待补赛果或缺 `match_id` 的对阵行，并同步切换赛程列表筛选，不能只跳到赛程列表顶部。
- 小组赛一键生成单循环成功后、瑞士轮草稿确认成功后，Admin 必须自动进入阶段赛程的“待赛果”视图；瑞士轮确认后优先聚焦该轮第一条待补赛果，瑞士轮撤回成功后则回到手动配对板，形成“生成 / 确认 -> 录赛果”和“撤回 -> 重新配对”的闭环。

- 全局“下一步”横幅不能只因为预赛阶段已存在就直接引导发布；如果当前阶段还缺分组、对阵、瑞士轮确认或淘汰赛槽位 / 判胜，必须优先指向当前阶段的具体操作。
- 活跃官方阶段画布本身必须暴露 `stage-workspace` 定位目标并支持焦点高亮；“查看预赛画布 / 去预赛主画布”等按钮在已有预赛阶段时也必须真正滚动并聚焦到当前阶段工作台，不能只在空阶段状态下有效。
- 淘汰赛对阵图主画布需要高亮第一个待手动补位槽、等待上游槽或待判胜节点，并允许把已落位队伍拖回待落位池取消落位，避免管理员只能找“清空”按钮；等待上一轮胜者自动进入的槽位必须显示“等上游 / 等待上游胜者”，和需要管理员拖队伍的空槽区分开，但仍允许手动拖拽修正。
- 淘汰赛对阵图拖拽补位、槽位互换或选择胜者成功后，页面必须自动定位到新的当前动作：下一个待补槽、下一个待判胜节点、等待上游槽或对阵图状态，避免管理员每次操作后重新扫整张图。
- 从预赛画布或右侧 inspector 点击“打开对阵图”时，也必须复用同一套当前动作定位逻辑，切换阶段后直接把焦点落到可操作槽位或待判胜节点。
- 淘汰赛对阵图的待落位队伍池只能显示该淘汰赛阶段配置里的入围 `teamIds`，不能退回整届参赛名单；6 队入围时，未进入淘汰赛的队伍不得出现在待落位池，也不得被拖进对阵图槽位。
- 淘汰赛对阵图的待落位队伍池保留拖拽主路径，同时支持点击队伍填入第一个待补槽；chip 复用“填入”动作标记，方便窄屏或触控板下快速补位。
- 淘汰赛对阵图已落位队伍必须在槽位状态和 chip `title` / `aria-label` 中提示可调整：可拖到其它槽位交换，也可拖回待落位队伍池移出；已判胜节点保持锁定。
- 淘汰赛阶段的“当前下一步”、阶段内导航和阶段状态概览必须复用同一套槽位语义和定位目标：只把需要管理员拖队伍的槽计入“待补”，等待上游胜者自动进入的槽显示为“等上游”；点击待补、等上游或判胜入口时要直接定位到第一个对应槽位 / 节点，不能只跳到整张对阵图顶部。
- 已生成淘汰赛阶段的首屏需要使用紧凑命令栏承载当前动作、待落位队伍查找、已落位数量和定位按钮；对阵图画布紧随其后，统计说明和下一步详情放到画布下方的可展开状态区。
- 淘汰赛对阵图存在待补槽时，命令栏和待落位池必须明确显示“下一槽”目标（轮次 / 节点 / 上位或下位）；点击待落位队伍时只填入这个高亮槽，chip 动作文案也要同步为“填入上位 / 填入下位”。
- 淘汰赛对阵图的空槽本身也必须说明落位语义：第一个待补槽显示“下一槽 · 上位 / 下位”和“拖队伍到这里，或点待落位队伍填入这里”，其它手动空槽显示“从待落位队伍池拖入”，等待上游槽显示“上一场判胜后自动进入，也可手动修正”。
- 已生成淘汰赛阶段的首屏不得再展示与命令栏重复的“拖拽淘汰赛对阵图”标题条；当前操作命令、待落位队伍池和对阵图应尽量进入首屏。
- 淘汰赛节点的胜者选择必须贴近当前对阵：当上位 / 下位都已落位时，节点内直接出现“选择胜者”双按钮判胜条，按钮使用完整队名并显示“胜”；槽位只负责拖拽落位 / 清空，胜者槽位在完成后明确高亮。
- 淘汰赛待判胜节点必须在节点内直接显示“点胜者后”的推进路径；“设为胜者”按钮需要通过 title / aria 明确胜者进入哪个节点、负者进入败者组或淘汰，避免管理员点之前不知道影响范围。
- 每个官方阶段主画布提供阶段内操作导航条，按分组/排赛/赛果/淘汰赛或配对/确认/赛果/淘汰赛快速定位，避免管理员在长画布里查找区域；导航条必须放在阶段拖拽工作台之后、赛程列表之前，不能只藏在底部状态抽屉里，也不能挡住首屏主要拖拽操作。
- 阶段内操作导航在窄屏下必须保持单行紧凑按钮条，不能变成多张纵向卡片挤占赛程管理页面。
- 预赛阶段还没有任何对阵时，不展示阶段内操作导航条；赛果、排名和淘汰赛入口继续收进“后续处理”抽屉，首屏只保留当前分组 / 排赛 / 配对工作台。
- 小组赛已经进入排赛优先态时，阶段内“分组”快捷入口必须直接展开并定位到被收起的分组拖拽画布，而不是只滚动到排赛工作台顶部或“设置与辅助”抽屉顶部；定位到小组数量时必须直接聚焦完整小组数量控制条。
- 阶段内操作导航在没有任何对阵时，赛果入口不得显示 `0/0`，需要显示“待排赛”等可理解状态；点击该入口时必须回到当前应执行的排赛 / 瑞士配对 / 对阵图动作，而不是跳到空赛程列表。
- 阶段内“赛果”入口在已有对阵时需要复用赛程待办语义：有待补赛果时进入“待赛果”并聚焦第一条，赛果已补齐但缺 `match_id` 时进入“缺 ID”并聚焦第一条。
- 阶段内操作导航的淘汰赛入口不能只显示“稍后”并跳到尚不可操作的淘汰赛区；它必须用“先排赛 / 先赛果 / 先确认 / 等排名”等短状态说明当前阻塞点，并定位到对应动作。
- 阶段状态抽屉只保留阶段概览指标，不再重复渲染“当前下一步”；下一步只通过主工作台、赛程空态、排名空态和阶段导航定位。
- 每个官方阶段主画布顶部只展示紧凑状态概览，集中显示分组 / 轮次 / 对阵图 / 对阵数量等运营指标，避免用多张说明卡重复解释流程。
- 在已经进入具体阶段的主工作台后，“后续处理”和“阶段概览”关闭态必须表现为紧凑状态条，只保留短标签和主状态；详细指标、赛程列表、排名和淘汰赛入口只能在展开后占用空间，避免这些后续信息像大卡片一样继续挤占首屏。
- 预赛还没有任何对阵时，“稍后处理”关闭态只能显示“排完赛再看赛果、排名、淘汰赛”这类状态摘要，不能继续用说明句解释流程，也不要在关闭态渲染隐藏的阶段指标。
- 已进入具体官方阶段后，默认布局需要先展示该阶段的主拖拽工作台；官方赛程控制台、基础设置和发布检查都收进画布后的折叠区，需要修正名单 / 赛制 / 发布时再展开。
- 已进入具体官方阶段后，不再单独渲染“官方赛程运营状态”条；名单、赛制、发布和 H5 状态归入“基础设置”紧凑抽屉，避免当前拖拽工作台之后继续出现重复运营状态。
- 当官方赛程控制台收进折叠区时，折叠态仍必须保留一条基础设置快捷命令栏，直接展示名单、赛制和发布状态；发布检查已通过时允许在该命令栏直接发布到 H5，未通过时提供展开设置入口。
- 当官方赛程控制台收进折叠区时，完整控制台内容必须延迟到展开后才挂载；关闭态只保留一条快捷命令栏，不再额外渲染完整 summary、名单 / 赛制 / 发布表单，避免它们继续进入首屏 DOM 和读屏顺序。
- 已进入具体官方阶段时，基础设置关闭态不再重复展示名单 / 赛制 / 发布指标；基础设置只保留当前缺项和展开入口，完整状态展开后再查看。
- 已进入具体官方阶段时，基础设置关闭态必须表现为小型工具条，不得再使用大卡片高度或完整控制台视觉重量；它只承担“当前缺项 / 展开设置 / 可发布时发布”。
- 当名单、赛制和预赛阶段都已就绪但预赛尚未排赛时，基础设置关闭态必须在主标题显示“基础设置已保存 · H5 未发布 / H5 可见”，辅助说明显示“当前只差上方阶段排赛”，不能继续用“先创建预赛对阵”暗示管理员需要展开基础设置才能排赛。
- 所有辅助抽屉、状态抽屉和赛程细节抽屉在关闭态只能显示 `summary`；内部按钮、表单和写入动作不得继续视觉占位或可见，避免“已折叠”区域仍然制造首屏复杂度。
- 小组赛优先支持手动逐场创建 BO2 对阵；一键生成 BO2 单循环作为辅助动作，比赛时间默认待定。
- 手动创建 / 修改小组赛、瑞士轮和淘汰赛对阵时，管理员未填写计划时间必须落库为空时间并在后台与 H5 显示“时间待定”；API 不得自动补当前时间。
- 小组赛支持创建加赛；加赛不计入积分，只用于管理员手动排序。
- 积分榜支持管理员手动排序覆盖。
- 积分 / 排名面板需要明确展示当前是自动排序还是手动覆盖；拖拽排名前需要有状态条提示“拖动左侧手柄可覆盖名次”，手动覆盖后需要标明绿色名次和恢复自动排序入口。
- 修改状态：未开始、已确认、进行中、待补录、已完赛、延期、取消。
- 支持删除错误 series。
- 阶段赛程行点击编辑后，编辑器在主画布赛程列表上方展开；右侧 inspector 只显示提示，避免编辑对象和编辑表单分离。
- 阶段赛程行需要直接标记“待补赛果”和“缺 N 个 match_id”，并支持从命令栏一键定位第一个待处理对阵。
- 展示来源：手动创建、小组赛生成、瑞士轮生成、淘汰赛对阵图生成。

验收：

- 已完赛但没有 match_id 的比赛可以显示人工赛果。
- 延期和取消必须填写原因。

### 4.8 赛果录入

功能：

- 为每一局录入比分、胜方、match_id。
- MVP 支持直接录入 series 总比分；小组赛和瑞士轮允许平局。
- 检测 OpenDota 返回结果与人工结果是否冲突。
- 允许解绑错误 match_id 并重新关联。
- 赛果确认后触发阶段积分榜重算或淘汰赛晋级。

验收：

- 重复 match_id 不允许保存。
- 人工胜方与 OpenDota 胜方冲突时进入“待确认”。
- 冲突状态下不自动推进排名或对阵图。

### 4.9 积分榜与 Bracket 管理

功能：

- 查看小组赛积分榜。
- 查看瑞士轮积分榜、轮次和 BYE。
- 查看单败或双败淘汰赛对阵图。
- 小组赛 MVP 使用胜 3 分、平 1 分、负 0 分。
- 手动重算积分榜。
- 手动修正排名、晋级队伍或对阵图节点。
- 填写手动修正原因。

验收：

- 排名修正必须进入审计日志。
- 用户端只展示已确认或已发布的排名和对阵图。

### 4.10 数据同步

功能：

- 查看 league_id 自动同步配置和最近执行时间。
- 查看后端自动发现的新比赛。
- 查看自动解析请求状态。
- 按 match_id 手动同步单场比赛。
- 按 league_id 手动触发一次发现任务。
- 手动请求 OpenDota 解析。
- 查看同步进度、失败原因、重试。
- 处理赛程自动关联失败和赛果冲突。

验收：

- 同步任务可追踪状态。
- 外部接口失败不会影响用户侧已有缓存数据。
- 管理员无需手动维护所有 match_id，只有自动关联失败时才需要介入。

### 4.11 互动标签管理

功能：

- 首版以“选手”为主工作对象，队伍标签后续扩展。
- 标签管理页默认列出数据库全部选手；管理员可按届次筛选，选中选手后查看该选手跨届全部标签。
- 选手列表支持按届次、选手名、Dota account_id、队伍、标签文本、创建人和审核状态搜索 / 筛选。
- 当选手存在待审核标签时，标签管理入口、选手队列和选手详情都需要显示待审数量提醒。
- 通过待审核标签、拒绝标签、隐藏已通过标签、恢复误隐藏 / 误拒绝标签，也可以删除测试或误建标签。
- 查看标签创建人、创建时间、点赞数、审核状态和审核原因。
- 为本地测试和运营纠偏，管理员可以直接为选手新增标签，并选择初始状态；普通 H5 仍只展示已通过标签。
- 为测试 H5 权重展示和运营纠偏，管理员可以直接增加或减少标签点赞数；后端必须保证点赞数不小于 0。

验收：

- 拒绝和隐藏标签不要求填写原因；管理员可直接执行。
- 普通用户无法看到待审核、已拒绝或已隐藏标签。
- 标签通过、拒绝、隐藏、恢复都必须进入审计日志。
- 管理员新增测试标签需要复用选手身份级去重规则，不因不同届次入口重复创建同文案标签。

### 4.12 权限与审计

功能：

- 管理管理员账号。
- 分配角色和作用范围。
- 查看审计日志。

验收：

- 所有写操作必须记录旧值、新值、操作者和时间。
- 超级管理员不能删除自己的最后一个超级管理员权限。

## 5. 部署

推荐部署到云服务器：

```text
admin.example.com    -> Nginx 静态站点
api.example.com/api  -> Nginx 反向代理到 Express API
```

最低要求：

- HTTPS。
- 管理后台域名不配置到小程序，只给管理员使用。
- API 域名配置到小程序 request 合法域名，并允许 H5 域名跨域访问。
- 数据库每日备份。
- 日志保留至少 14 天。
