## 1. 页面定位

比赛详情页是小程序的核心传播页。它不是单纯的数据表，而是“赛后战报 + 复盘 + 社区分享”的组合页面。视觉上应该保留 Dota 2 暗色、阵营对抗、英雄头像、装备图标和长页面滚动复盘的感觉。

## 2. 截图结构拆解

### 2.1 顶部导航

内容：

- 返回按钮。
- 标题：比赛 + match_id。
- 更多操作和分享。

产品要求：

- 小程序顶部使用自定义导航栏或微信原生导航栏。
- 分享按钮要明显，但不能遮挡标题。

### 2.2 比赛摘要卡

截图信息：

- 联赛名。
- 胜方文案：例如“死亡之拳 胜利”。
- 比分：33 vs 27。
- 时长：47:05。
- 阵营：天辉、夜魇。
- 比赛编号、模式、结束时间。

数据字段：

- `match_id`
- `league_id`
- `radiant_score`
- `dire_score`
- `radiant_win`
- `duration`
- `game_mode`
- `start_time`
- `series` 和 `teams` 的人工维护信息

MVP 要求：

- 必须首屏展示胜方、比分、时长。
- 如果没有队伍名，展示“天辉”和“夜魇”。

### 2.3 MVP 卡片

截图信息：

- MVP 标签。
- 玩家名、英雄、英雄大图。
- 击杀、死亡、助攻。
- 参战率、伤害比、评分。
- 称号。

计算建议：

- MVP 先用规则评分，不依赖机器学习。
- MVP 评分可按胜方优先，结合 KDA、参战率、英雄伤害占比、建筑伤害、治疗、承伤、GPM/XPM。
- 评分字段可缓存到 `match_awards`，便于后续调整算法。

MVP 规则示例：

```text
score =
  kda_score * 0.25 +
  participation_score * 0.25 +
  hero_damage_share * 0.20 +
  objective_score * 0.15 +
  economy_score * 0.15
```

### 2.4 双方选手数据

截图信息：

- 分为天辉和夜魇两块。
- 每个玩家行展示英雄头像、等级、昵称、徽章、分路/定位标签。
- 展示参战率、伤害占比、KDA。
- 右侧展示装备、背包、中立装备。
- 首个展开行展示更细数据：正补/反补、GPM、XPM、净值、治疗、拉野、控制时间、买活等。
- 加点顺序以技能图标序列展示。

MVP 字段：

- `hero_id`
- `level`
- `kills`
- `deaths`
- `assists`
- `gold_per_min`
- `xp_per_min`
- `net_worth`
- `last_hits`
- `denies`
- `hero_damage`
- `tower_damage`
- `hero_healing`
- `damage_taken`
- `item_0` 到 `item_5`
- `backpack_0` 到 `backpack_2`
- `item_neutral`
- `ability_upgrades_arr` 或 `ability_upgrades`
- `lane`

交互：

- 默认每队显示 5 行。
- 点击玩家行展开高级数据。
- 装备图标支持点击查看名称，MVP 可先做长按或弹窗。

### 2.5 Ban & Pick 时间线

截图信息：

- 中央纵轴，左右对应两队。
- 每一步显示序号、Ban/Pick 标签、玩家名或英雄名、英雄头像。
- Ban 红色，Pick 绿色。

数据字段：

- `picks_bans`
- `order`
- `is_pick`
- `team`
- `hero_id`
- 可选 `player_slot`

MVP 要求：

- 按 `order` 从小到大排序。
- 缺数据时显示“该比赛暂未解析 Ban/Pick”。

### 2.6 视野复盘

截图信息：

- Dota 地图背景。
- 有圈、线、点位等复盘标记。
- 底部有时间轴。

数据可行性：

- OpenDota 解析数据可提供部分地图、目标和视野相关字段，但完整可播放复盘成本较高。
- MVP 建议先做“关键目标小地图”：肉山、塔、兵营、击杀高发区域。
- 第二阶段再做时间轴播放。

MVP 字段：

- `objectives`
- `teamfights`
- `players.lane_pos`
- `obs_log`、`sen_log` 如果存在

### 2.7 趋势图

截图信息：

- 上半部分：个人经济曲线，多条线。
- 下半部分：总经济差、经验差。
- 支持经济和经验切换。

数据字段：

- `players.gold_t`
- `players.xp_t`
- 由双方累计计算 `gold_advantage`
- 由双方累计计算 `xp_advantage`

MVP 要求：

- 图表懒加载，滚动到区域再渲染。
- 小屏幕下图例可换行。
- 未解析时隐藏。

### 2.8 分路数据

截图信息：

- 三条路对位卡片：优势路、中路、劣势路。
- 左右颜色代表双方。
- 展示英雄和玩家名。

数据字段：

- `lane`
- `lane_role`
- `team`
- 手动维护队伍阵营映射

MVP 要求：

- 根据 OpenDota lane 推断。
- 推断失败时只展示阵容，不展示对位结论。

### 2.9 数据对比

截图信息：

- 选项：输出、参团、输出经济比等。
- 横向条形图，对比双方核心指标。
- 左右颜色与阵营对应。

指标建议：

- 输出：英雄伤害占比。
- 参团：参战率。
- 经济：GPM、净值占比。
- 承伤：承伤占比。
- 推进：建筑伤害。
- 支援：治疗量。

### 2.10 聊天记录

截图信息：

- 按时间展示阵营、时间、玩家、英雄、发言。
- 长页面底部模块。

数据字段：

- `chat`
- `time`
- `type`
- `unit`
- `key`
- 通过 player_slot 或 hero 关联玩家。

要求：

- 只展示比赛内公开聊天。
- 敏感词过滤可在后续加入。
- 没有解析数据时显示空状态。

## 3. 视觉规范建议

整体：

- 暗色底，减少纯黑，使用深蓝灰和深红渐变承托阵营对抗。
- Radiant 颜色：绿色或青绿。
- Dire 颜色：红色或玫红。
- 卡片圆角控制在 8px 左右。
- 数据模块用清晰标题，不用大段说明文字。

移动端约束：

- 375px 宽度下不能横向滚动。
- 英雄名、玩家名需要单行截断。
- 装备图标固定尺寸，避免加载后布局跳动。
- 长页面增加“回到顶部”悬浮按钮。

| --- | --- | --- | --- |
| 摘要 | 可用 | 可用 | 必显 |
| 选手 KDA | 可用 | 可用 | 必显 |
| 装备 | 可用 | 可用 | 必显 |
| 加点 | 可能缺失 | 可用 | 有则显示 |
| Ban/Pick | 可能缺失 | 可用 | 有则显示 |
| 曲线图 | 通常需解析 | 可用 | 有则显示 |
| 视野复盘 | 需解析 | 可用 | 第二阶段强化 |
| 聊天记录 | 需解析 | 可用 | 有则显示 |

## 6. 验收清单

- 首屏展示 match_id、胜方、比分、时长。
- 10 名玩家均能看到英雄、KDA、装备。
- 数据缺失时模块级降级，不影响整页。
- Ban/Pick 顺序正确。
- 图表颜色与阵营一致。
- 长昵称、长英雄名、长聊天不撑破布局。
- 微信分享标题包含双方队伍和比分。
