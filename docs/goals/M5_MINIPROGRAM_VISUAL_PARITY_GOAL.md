# M5 Mini Program Visual Parity Goal

状态：已完成

最后更新：2026-06-08

## 目标

完成微信小程序端的可用 UI 收束，让小程序在公开浏览路径上以 H5 端为视觉和数据密度基准，同时修复微信开发者工具中出现的排版混乱问题。

本轮追加目标：小程序端比赛记录、比赛详情、选手和队伍等公开页必须继续与 H5 读取同一后端契约；比赛详情补齐 H5 已展示的英雄头像、英雄阵容、物品栏 / 背包 / 中立物品、神杖 / 魔晶、技能加点、天赋图例、Ban/Pick、眼位地图、趋势对比和聊天记录。小程序专属登录互动能力继续保留在微信端，不要求 H5 拥有相同写入口。

像素级复刻追加目标：以 H5 当前 React 页面为唯一视觉基准，继续收紧小程序端公开页面的元素完整度和布局差距。比赛详情必须复刻 H5 的天赋树 SVG 造型、眼位 SVG 图标、眼位时间轴拖动筛选、BP 中轴时间线、经济 / 经验差 SVG 折线图、选手经济 SVG 折线图、双方对比条和装备栏尺寸体系；开发者工具导入 `apps/miniprogram/dist` 后应能看到本轮新版。

完美还原追加目标：以 `apps/mobile-web/src/App.tsx` 和 `apps/mobile-web/src/styles.css` 当前实现为唯一视觉 / 信息 / 交互基准，逐页还原小程序首页、赛事阶段、赛程、比赛记录、比赛详情、选手列表、选手详情、队伍列表、队伍详情和我的页。小程序不能再只保持“同一气质”，而应尽量在导航外壳、赛事上下文条、卡片结构、列表密度、英雄阵容、选手 / 队伍数据卡、详情页 profile hero、常用英雄、状态色、字号、间距、圆角和空状态上贴近 H5 当前页面。

小程序继续承担登录后互动能力：微信登录、Dota/Steam 数字账号绑定、选手标签提交、已审核标签点赞 / 取消点赞。公开赛事、赛程、战报、选手和队伍页面保持未登录可浏览。

## 执行边界

- 不复用 H5 的 DOM/CSS 布局实现。
- 不在小程序里复制 H5 的复杂漂浮标签动效；小程序优先稳定、清晰、可点击。
- 不改造后端认证、标签审核和点赞数据模型。
- 不扩展报名、支付、论坛或完整用户资料编辑。
- 不让小程序自行计算排名、晋级或 bracket；继续读取后端结果。

## 视觉方向

- 深色赛事数据界面，与 H5 的暗色竞技氛围一致。
- 以金色作为主行动和当前状态色，青绿色作为成功 / 可用状态辅助色。
- 卡片圆角控制在 8px 内，保留 H5 的克制边框、轻微高光和数据密度。
- 页面优先服务扫读：标题、状态、比分、队名和关键统计不互相挤压。
- 微信端采用稳定 flex 布局和明确间距，减少 `grid`、`gap`、复杂伪元素和 H5 特有样式造成的兼容风险。

## 小程序范围

需要完成：

- 全局小程序样式重置，尤其是微信 `button` 默认边框、外边距和行高。
- 首页、赛程、比赛记录、赛事阶段、选手列表、选手主页、队伍列表、队伍主页、比赛详情和我的页布局稳定。
- 比赛记录卡展示与 H5 一致的天辉 / 夜魇 5v5 英雄阵容预览。
- 比赛详情展示与 H5 一致的战报核心模块：双方选手、英雄头像、装备、技能、天赋、BP、眼位、趋势和聊天。
- Dota 英雄、物品、技能、小地图和神杖 / 魔晶素材全部本地化进小程序包内；API 公开静态路由保留为备用能力，但小程序战报展示不依赖远端素材。
- 选手页标签输入框和点赞按钮在微信小程序中不撑破布局。
- 我的页 API 地址输入、账号绑定输入和登录操作保持可用。
- tabBar 和导航色彩与 H5 主视觉一致。
- 赛事阶段、赛程、比赛记录、选手列表和队伍列表使用 H5 同构的信息组织，不再保留早期小程序简化列表。
- 选手 / 队伍详情页使用 H5 profile hero、胜率摘要、常用英雄和比赛记录结构，小程序专属标签输入与点赞模块作为追加能力保留。

## 验收标准

1. 微信开发者工具中页面不再出现按钮、卡片、文本互相覆盖或横向撑破。
2. 首页、赛程、比赛记录、选手、我的五个 tab 页面可正常浏览。
3. 选手主页可看到标签输入框，登录后可提交标签。
4. 已审核标签可点赞 +1 / 取消点赞，按钮布局稳定。
5. 我的页可登录、绑定 Dota `account_id` 或 SteamID64，并展示无比赛记录空状态。
6. 小程序视觉颜色、卡片质感、字体层级和 H5 端保持同一产品气质。
7. `npm run build:miniprogram:local` 成功。
8. `npm --workspace @mrjz/miniprogram run typecheck` 和 `npm --workspace @mrjz/api run typecheck` 成功。
9. API 可公开返回 Dota 英雄、物品、技能、小地图和神杖 / 魔晶 SVG 素材，且路由使用白名单路径校验。
10. 小程序构建产物包含全量 `assets/dota` 与 `assets/svg`，战报图片在微信开发者工具中从本地包内加载。
11. 更新 `docs/PROGRESS.md` 记录本轮完成内容。
12. 比赛详情天赋树不再是简化圆点 / 文字图例，而是 H5 同源树枝和弧点 SVG。
13. 眼位地图使用阵营染色 SVG 图标，并提供可拖动时间轴；拖动时只显示对应时间点仍有效的眼位。
14. 趋势区不再使用简化柱状卡，改为 H5 同构的经济 / 经验差折线图和选手经济折线图。
15. Ban / Pick 区不再是单列列表，改为 H5 同构的中轴左右分布时间线。
16. 赛事阶段页包含 H5 同构的赛事上下文条、阶段切换、积分榜 / 当前轮次 / 淘汰赛摘要。
17. 赛程页包含 H5 同构的状态筛选、正序 / 倒序切换、赛程统计和阶段 / 轮次分组。
18. 比赛记录页与首页最新战报统一复用 H5 风格 5v5 英雄阵容卡。
19. 选手列表页从小程序简化搜索列表升级为 H5 数据榜卡片，包含排序条、战队标识、胜率、KDA、GPM/XPM 和常用英雄。
20. 队伍列表和详情页复刻 H5 profile-list-card / profile-hero 结构，并继续读取后端统计。
21. 比赛详情页双方选手数据必须和 H5 一样默认折叠：主行保留英雄、选手、KDA、参战、伤害和装备，进阶统计与技能加点只在点击展开后显示。
22. 选手数据榜排序必须和 H5 完全一致：场次、胜率、KDA、击杀、GPM、XPM、伤害、建筑、承伤和名字都可切换，并按 H5 的空值与同名兜底规则排序。
23. 赛程页状态筛选和卡片状态文案使用 H5 的 `未开始 / 待补录 / 已完赛 / 延期`，不直接暴露后端内部状态词。

## 完成记录

- 补齐 Taro `designWidth: 375` 对应的 `deviceRatio: { 375: 2 }`，避免生成 WXSS 出现 `NaNrpx` 导致微信端排版失控。
- 小程序全局样式改为微信端稳定的 flex + margin 布局，移除主要 `grid`、`gap`、`inline-flex` 依赖。
- 重置微信 `button` 默认边框、外边距和伪元素边框。
- 小程序导航栏和 tabBar 改为与 H5 端一致的深色 / 金色视觉体系。
- 已通过 `npm run build:miniprogram:local` 和 `npm --workspace @mrjz/miniprogram run typecheck`。
- 二次视觉收束以 H5 为唯一视觉源：移除微信原生 tabBar，改用自绘 `app-shell`、自定义顶部栏和底部悬浮导航。
- 首页补齐 H5 同构 hero：双向 Dota hero 滚动背景、MRJZ 品牌核心、三项快捷入口和统计条，并在 Taro 构建时复制 H5 hero 素材。
- 赛事入口、赛程卡、比赛记录卡和详情页 hero 面板统一使用 H5 的深色、金色边框和 Radiant / Dire 渐变语言。
- 导航修正为 H5 行为：首页赛事入口点击后进入“赛事阶段”，二级页展示 6 个 H5 主导航；小程序专属“我的”入口不再占用 H5 主导航位置。
- 比赛记录卡补齐双方英雄阵容缩略图，资源 URL 指向小程序包内 `/assets/dota`。
- 比赛详情补齐 H5 战报模块：英雄头像、装备 / 背包 / 中立物品、神杖 / 魔晶、技能加点、天赋图例、Ban/Pick、眼位地图、趋势对比和聊天。
- API 增加公开 Dota / SVG 静态素材路由，使用路径段白名单和后缀 content-type 白名单，作为后续远端素材策略的备用出口。
- 小程序恢复全量本地 Dota 素材，源码 `src/assets` 约 59MB；微信开发者工具应导入或刷新 `apps/miniprogram/dist`。
- 像素级复刻追加轮补齐 H5 细节：天赋树改为同源 SVG data URL；眼位地图使用阵营染色 SVG 图标和 15 秒步进 Slider 时间轴；BP 时间线改为中轴左右布局；趋势区改为经济 / 经验差与选手经济 SVG 折线图；装备栏、背包、中立物品、神杖 / 魔晶和天赋图标尺寸回到 H5 的紧凑体系。
- 完美还原追加轮按 H5 页面结构继续收紧小程序公开页：补齐赛事上下文条、赛程筛选 / 排序、阶段页积分榜与当前轮次、首页和记录页统一战报卡、选手数据榜、队伍列表卡、选手 / 队伍详情 profile hero 和常用英雄模块。
- 小程序专属登录、账号绑定、选手标签提交和真实点赞能力继续保留在微信端独有区域，不占用 H5 主导航和公开页主视觉。
- H5 parity 修正轮继续消除交互差异：比赛详情双方选手行改为 H5 式可点击折叠，装备常显、进阶统计和技能加点展开后显示；选手榜排序项和排序规则补齐到 H5 全量矩阵；赛程筛选和赛程卡状态文案改回 H5 的用户可见状态。

## 完成定义

用户可以在微信开发者工具里以测试 AppID 打开小程序，完成公开浏览和登录互动的主要路径；首页、赛事阶段、赛程、比赛记录、比赛详情、选手和队伍页面的元素组织、信息密度和视觉层级都以 H5 当前页面为基准；比赛记录和比赛详情不再缺英雄头像、装备、技能、BP、眼位、趋势或聊天等 H5 核心战报内容；小程序专属登录、绑定、标签提交和点赞能力稳定保留。
