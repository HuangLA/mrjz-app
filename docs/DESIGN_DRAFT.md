# 页面设计稿 v0

最后更新：2026-05-13

## 1. 设计方向

视觉基调：深色电竞数据面板，强调 Dota 2 的阵营对抗和赛后复盘感。用户侧用高密度信息、英雄头像、装备图标、趋势图和标签云做记忆点；管理端保持安静、清晰、可操作，重点是列表、筛选、异常处理和同步状态。

设计原则：

- 小程序和 H5 共用移动端页面结构，优先保证手机宽度下的数据可读。
- Web Admin 使用桌面运营工具布局，不沿用用户端的强视觉风格。
- Radiant 使用绿色语义，Dire 使用红色语义。
- 详情页允许长滚动，但每个模块必须有明确标题和可折叠/降级策略。
- 所有数据缺失状态都按模块降级，不让整页失败。

移动端排版尺度：

- 页面主标题控制在 App 内页标题尺度，避免营销页式大字。
- 模块标题偏小而清楚，正文以高密度数据阅读为主。
- 辅助信息、match_id、解析状态、时间等使用更小字号和低对比度。
- 比分、MVP、标签云可以略突出，但只作为数据重点，不作为大 hero。
- 卡片内边距保持紧凑，参考赛后战报长页面的密度。

## 2. 用户侧页面

### 2.1 首页

目标：作为赛事入口页，先让用户明确自己要查看哪一届比赛，再进入该届的次级数据页面。

模块：

- 赛事入口列表：第一届、第二届、第三届等所有可公开查看的赛事。
- 每届入口只展示必要识别信息：赛事名、League ID、生命周期状态、开赛时间和最近一场比分摘要。
- 点击某届后进入该届赛事阶段页，并把后续赛程、比赛记录、选手、队伍页面的数据范围锁定到该届。
- 首页不展示底部浮动导航，避免用户未选择赛事时看到次级页面入口。
- 次级页面顶部显示轻量“当前赛事”上下文条，并提供返回首页切换届数的入口。
- 下一场赛程、最新赛果、选手榜、队伍榜、比赛记录等内容全部放到次级页面，不在首页展开。

方向：首页不做赛事仪表盘，只做清晰的届次选择器。这样旧赛事入口仍然稳定保留，同时用户进入任何数据页前都能先确认正在查看哪届比赛。

### 2.2 赛程页

目标：按日期查看比赛安排。

模块：

- 日期分组。
- 状态筛选：全部、未开始、待补录、已完赛、延期。
- 赛制筛选：小组赛、瑞士轮、淘汰赛。
- 赛程卡：时间、队伍、BO、阶段、状态。
- 已完赛但未关联 match_id 时显示“人工赛果”。

方向：以扫描效率为主，状态标签要清楚。

### 2.2.1 赛事阶段页

目标：让用户理解整个赛事进度。

模块：

- 阶段切换：小组赛、瑞士轮、淘汰赛。
- 小组赛：小组积分榜、晋级线、组内赛程。
- 瑞士轮：总积分榜、当前轮、历史轮次、BYE 标识。
- 淘汰赛：移动端纵向 bracket。

方向：阶段页是“赛事地图”，赛程页是“时间列表”；两者都要存在。

### 2.3 比赛列表

目标：查看本联赛已同步比赛。

模块：

- 筛选：赛季、队伍、选手、解析状态。
- 比赛卡：比分、胜方、时长、match_id、解析状态。
- 同步来源标识：自动同步、手动补录、待确认。

方向：区别“赛程”与“比赛记录”，比赛列表更偏赛后数据。

### 2.4 比赛详情

目标：赛后复盘核心页。

模块：

- 比赛摘要：胜方、比分、时长、match_id、赛季。
- MVP 卡片。
- 双方玩家数据。
- Ban/Pick 时间线。
- 趋势图。
- 分路和数据对比。
- 聊天记录。

方向：参考截图的长页面结构，但 v0 先把层级和节奏定下来，后续再做高保真英雄/装备细节。

### 2.5 选手主页

目标：展示选手数据和社区印象。

模块：

- 选手头部：头像、昵称、队伍、绑定状态。
- 核心数据：场次、胜率、KDA、常用英雄。
- 标签云：点赞越多越大。
- 近期比赛。

方向：标签云放在数据之后，让页面既有硬数据又有社区味道。

### 2.6 队伍主页

目标：展示队伍资料、成员、近期赛程和社区标签。

模块：

- 队伍头部：Logo、队名、战绩。
- 当前阵容。
- 近期赛程和赛果。
- 队伍标签云。

方向：队伍页比选手页更强调阵容和赛程。

### 2.7 我的

目标：登录用户查看个人联赛数据。

模块：

- 登录状态和绑定状态。
- 我的赛季数据。
- 我的常用英雄。
- 我的近期比赛。
- 绑定申请入口。

方向：只展示本联赛数据，避免做成泛 Dota 数据页。

### 2.8 H5 兜底页

目标：小程序审核延迟时可直接分享和浏览。

模块：

- 公开首页。
- 公开赛程和比赛详情。
- 只读标签云。
- 打开小程序入口。

方向：H5 第一版不把登录作为阻塞项，优先让比赛链接可传播。

## 3. Web Admin 页面

### 3.1 工作台

目标：管理员进入后知道今天要处理什么。

模块：

- 当前赛季概览。
- 自动同步状态。
- 待补录赛果。
- 自动关联失败。
- 赛果冲突。

方向：运营任务列表优先，少做装饰。

### 3.2 赛程和赛果管理

目标：创建赛程、录入比分、处理 match_id，并归属到赛事阶段。

模块：

- 筛选区。
- 赛程表格。
- 赛事、阶段、轮次筛选。
- 快速录入比分。
- match_id 关联状态。

方向：桌面表格是主视图，抽屉或弹窗做编辑。

### 3.2.1 赛事管理

目标：管理小组赛、瑞士轮和淘汰赛。

模块：

- 赛事创建和阶段配置。
- 小组赛分组与循环赛程草稿。
- 瑞士轮下一轮配对草稿。
- 淘汰赛 bracket 和种子位。
- 积分榜重算、阶段锁定、晋级队伍确认。

方向：所有自动生成内容先作为草稿，管理员确认发布后才进入用户端。

### 3.3 自动同步控制台

目标：配置 league_id、查看自动同步任务。

模块：

- league_id 配置。
- 同步频率。
- 自动请求解析开关。
- 任务队列状态。
- 失败重试。

方向：让管理员清楚“系统正在自动做什么”和“哪些需要人介入”。

### 3.4 队伍和选手管理

目标：维护队伍、成员、选手绑定。

模块：

- 队伍列表。
- 选手列表。
- 绑定审核。
- 赛季成员变动。

方向：以筛选、搜索、批量维护为主。

### 3.5 标签审核

目标：处理用户添加的选手/队伍标签。

模块：

- 标签列表。
- 目标类型筛选。
- 点赞数排序。
- 隐藏/恢复。
- 举报记录。

方向：后台不参与创作标签，只负责治理。
