# Dota 2 社区赛平台 PRD

最后更新：2026-05-13

## 1. 背景

现有网页端项目 `mrjz-dota2-tournament-stats` 已经覆盖联赛比赛记录、比赛详情、选手统计、战队数据、成就和数据同步能力。新项目要把用户侧查看体验迁移到微信小程序，并同步提供手机网页 H5 作为审核延迟和分享场景的兜底入口，同时新增云端后端、网页管理后台、赛程维护、赛果维护、登录体系和管理员权限能力。

小程序和手机网页端的定位不是通用战绩查询工具，而是“特定 Dota 2 联赛的赛事信息和数据展示端”。用户看到的数据必须来自本联赛、本赛季、本平台维护的队伍和选手关系。管理员不在小程序或 H5 里做复杂录入，而是在独立 Web Admin 中控制数据。

## 2. 产品目标

1. 观众可以快速查看当前赛季赛程、已完赛比赛列表和比赛详情。
2. 参赛选手登录后可以查看自己在本联赛内的战绩、英雄表现、比赛历史和关键指标。
3. 管理员可以通过网页后台创建赛程、配置联赛编号、录入必要赛果，并查看或纠正后端自动同步结果。
4. 比赛详情页参考提供的理想图，形成移动端可读的完整赛后复盘页。
5. 手机网页端可在小程序审核延迟时承担公开展示和分享落地页能力。
6. 技术上复用现有网页端的数据理解和同步经验，小程序和 H5 专注展示体验，网页后台专注高效管理操作。
7. 后端提供比赛管理系统，统一支持普通小组赛、瑞士轮和淘汰赛，前端能按赛事阶段展示赛程、积分榜和 bracket。

## 3. 用户角色

| 角色 | 权限 | 典型需求 |
| --- | --- | --- |
| 游客 | 查看公开赛程、公开比赛列表、比赛详情、基础榜单 | 看今晚有没有比赛，看某一场谁赢了 |
| 登录用户 | 游客权限，绑定或申请绑定 Dota 2 account_id | 进入“我的”，查看自己的联赛数据 |
| 参赛选手 | 登录用户权限，展示本联赛个人数据 | 看自己胜率、英雄池、KDA、近期比赛 |
| 队伍管理员 | 管理本队成员资料，确认赛程结果，提交 match_id | 维护队伍名单，协助录入比赛结果 |
| 赛事管理员 | 管理赛季、队伍、选手、赛程、赛果、同步任务 | 维护整个联赛运行 |
| 超级管理员 | 用户权限、管理员分配、系统配置 | 管理后台权限和联赛配置 |

## 4. 范围定义

### 4.1 MVP 范围

1. 微信登录和用户体系。
2. 赛季、联赛、队伍、选手基础资料。
3. 赛程列表和赛程详情。
4. Web Admin 手动录入赛程、比分、赛果、match_id。
5. 比赛记录列表：按赛季、联赛、队伍、选手、状态筛选。
6. 比赛详情页：比分、胜负、双方阵容、10 名选手数据、装备、加点、Ban/Pick、经济和经验曲线、分路对位、聊天记录。
7. 我的数据：只展示该用户绑定账号在本联赛内的数据。
8. OpenDota 自动同步：管理员配置 league_id 后，后端定时发现新比赛、拉取详情、请求解析并缓存。
9. Web Admin 同步状态、失败重试和审计日志。
10. 云服务器部署后端 API、数据库、缓存和同步任务。
11. 选手主页和队伍主页的互动标签：登录用户可添加标签、点赞标签，点赞越多展示越醒目。
12. 手机网页 H5：提供公开赛程、比赛列表、比赛详情、选手主页、队伍主页和标签云只读展示。
13. 比赛管理系统：赛事、阶段、轮次、对阵、积分榜、瑞士轮配对草稿、淘汰赛 bracket。
14. 每届赛事英雄榜：按场均或本届聚合口径统计趣味称号，展示称号获得者和候选前五。

### 4.2 暂不做

1. 小程序内支付、报名收费、票务。
2. 即时聊天和社区论坛。
3. 实时直播数据和观战。
4. 全 Dota 账号历史战绩查询。
5. 完全无人值守的自动判罚和自动发布赛程；MVP 只做规则辅助生成，需管理员确认发布。
6. 复杂运营大屏、多租户 SaaS 化、可视化拖拽编排后台。
7. H5 第一版不强制做完整登录和互动写操作，优先作为公开展示兜底。

## 5. 用户侧展示页面

小程序和手机网页 H5 共享大部分用户侧信息架构。小程序优先承载登录、我的数据、标签添加和点赞；H5 第一版优先承载公开展示和分享链接，后续再补登录互动。

### 5.1 首页

目标：让用户进入后知道当前赛季、近期赛程和最近结果。

内容：

- 当前赛季卡片：赛季名、联赛 ID、进行阶段、比赛总数。
- 最近赛程：时间、队伍、BO 类型、状态。
- 最新赛果：比分、胜方、比赛时长、match_id。
- 入口：赛程、比赛、选手、我的。

验收：

- 首屏能看到下一场比赛和最近一场完赛结果。
- 切换赛季后所有数据范围同步变化。

### 5.2 赛程页

目标：展示管理员维护的赛事安排。赛程由管理员负责，赛后比赛详情优先由后端根据 league_id 和 match_id 自动补全。

内容：

- 按日期分组的赛程列表。
- 状态：未开始、已确认、进行中、待补录、已完赛、延期、取消。
- 筛选：赛事、赛季、队伍、比赛阶段、轮次、状态。
- 赛程详情：队伍、BO 类型、比赛时间、房间信息、备注、管理员录入的赛果。
- 阶段视图：小组赛按小组和轮次展示，瑞士轮按轮次展示，淘汰赛按 bracket 节点展示。

验收：

- 未关联 match_id 的完赛赛程也能显示人工赛果。
- 小组赛赛程标题不重复显示只有一轮的“第一轮”，直接显示“小组赛”；加赛仍单独标注。
- series 关联任一 match_id 后可展开查看全部单局槽位、单局赛果和关联状态；点击已关联的单局进入对应比赛详情，不默认只打开第一局。
- 同一赛事内可以切换小组赛、瑞士轮和淘汰赛阶段。

### 5.2.1 赛事阶段、积分榜和 Bracket

目标：让用户理解当前赛事进展，而不是只看到零散比赛。

内容：

- 赛事总览：赛事名、当前阶段、阶段状态、晋级规则。
- 小组赛：小组积分榜、组内赛程、晋级线。
- 瑞士轮：当前轮、历史轮次、总积分榜、晋级线、BYE 标识。
- 淘汰赛：移动端纵向 bracket、每轮节点、比分、晋级状态。

验收：

- 小程序和 H5 都能展示三种赛制。
- 积分榜和 bracket 数据由后端返回，前端不自行计算排名。

### 5.3 比赛记录列表

目标：查看特定联赛的历史比赛。

内容：

- 卡片列表：胜负、比分、时长、队伍、开赛时间、match_id、解析状态。
- 筛选：赛季、联赛 ID、队伍、选手、英雄、是否已解析。
- 排序：时间倒序、时间正序、时长、总击杀。

数据来源：

- `schedules` 提供人工维护上下文。
- `matches` 提供后端自动从 OpenDota 同步后的赛后数据。

验收：

- 比赛列表只出现当前平台允许展示的联赛和赛季数据。
- OpenDota 未解析时显示基础数据和“高级数据待解析”状态。

### 5.4 选手主页

目标：展示某个选手在当前入口届次内的数据，同时承载跨届参赛历史和社区互动标签。

内容：

- 选手基础信息：昵称、头像、Dota 2 account_id、所属队伍。
- 本届数据：场次、胜率、KDA、GPM、XPM、伤害、承伤、常用英雄、近期比赛。
- 跨届参赛历史：优先展开当前入口届次比赛记录，往届比赛按届次折叠。
- 标签云：H5 在选手页上方展示已审核通过的选手应援标签，按点赞权重放大，并用漂浮气泡增强互动感；H5 点击只播放本地应援反馈，不实际点赞 +1。
- 添加标签：小程序登录用户可输入短标签并提交，提交后等待管理员审核。
- 标签点赞：小程序登录用户可为已通过标签点赞或取消点赞，不需要管理员审核。

验收：

- 未登录用户和 H5 用户可以查看已通过标签，H5 可触发本地应援动效，但不能添加、实际点赞或举报。
- 小程序点赞已有已通过标签无需审核；提交新标签必须审核。
- 待审核、拒绝和隐藏标签不能在 H5 展示。
- 同一用户对同一标签只能点赞一次。
- 同一选手下相同或近似相同标签需要跨届归并，避免从不同届次入口重复刷屏。
- 从任意届次入口进入同一选手主页时，已审核标签云保持一致；比赛记录优先显示该入口届次，往届记录默认折叠。
- 标签字数、允许字符、频率和去重需要后端校验；标签内容是否展示由管理员审核决定。
- 管理员可在 Web Admin 通过、拒绝、隐藏或恢复标签。

### 5.5 队伍主页

目标：展示队伍资料和队伍比赛数据。队伍社区标签留作后续扩展，不进入首个标签审核闭环。

内容：

- 队伍基础信息：队伍名、简称、Logo、当前赛季成员。
- 队伍数据：战绩、胜率、近期赛程、近期比赛、常用英雄或阵容倾向。
- 队伍标签：后续可按选手标签同样的审核模式扩展。

验收：

- 队伍标签和选手标签未来需要互相独立。
- 队伍解散或赛季切换后，历史标签未来仍需按赛季范围展示。

### 5.5.1 每届英雄榜

目标：为每届赛事提供独立的趣味数据榜单，让观众快速看到本届赛事最突出的选手。

统计规则：

- 普通数据称号按场均值排名；购买次数、暴走次数、指定英雄选择次数和击杀痛苦魔方等触发类称号按本届总次数排名；`PlayBoy` 按本届不同英雄数排名。
- 只统计本届赛事中参赛 5 场及以上的选手。
- 榜单由后端按本届赛事 OpenDota 原始比赛数据统一聚合，H5 和小程序只展示结果。
- 每个榜单默认展示当前称号获得者；点击展开后展示候选前五名、场均值或聚合值、总计和参赛场数。
- 老毒物、止痛药、化龙、老阴B 和 KS 的实际触发条件由后端计算，H5 和小程序在说明位置只显示“触发条件隐藏”。
- 如果某项字段全员缺失或没有满足 5 场门槛的选手，该榜单显示空态，不前端临时推断。

### 5.6 比赛详情页

目标：作为核心复盘页，参考截图实现移动端沉浸式详情。

核心模块：

- 比赛头部：联赛名、match_id、胜方、比分、时长、模式、结束时间、分享。
- MVP 卡片：玩家昵称、英雄、K/D/A、参战率、伤害占比、评分或徽章。
- 双方阵容数据：玩家、英雄、等级、参战率、伤害占比、KDA、装备、背包、中立物品、经济、加点。
- Ban & Pick：按顺序展示禁选时间线，区分 Radiant 和 Dire。
- 视野复盘：小地图事件或简化视图，MVP 可先做静态热区，后续再做可播放轨迹。
- 趋势图：个人经济、总经济差、经验差。
- 分路数据：优势路、中路、劣势路对位。
- 数据对比：输出、参团、经济、承伤、治疗、建筑伤害等。
- 聊天记录：来自 OpenDota 解析数据，按时间和阵营展示。

验收：

- 重要信息在手机宽度下不横向溢出。
- 未解析字段有降级视图，不能整页报错。
- 可分享到微信会话。

### 5.7 我的

目标：用户查看自己在本联赛的个人数据。

内容：

- 微信登录状态。
- 绑定 Dota 2 account_id 或 Steam 资料。
- 本联赛统计：场次、胜率、KDA、GPM、XPM、伤害、承伤、常用英雄。
- 近期比赛记录。
- 成就和高光。

约束：

- 所有统计只聚合本平台赛季和联赛内比赛。
- 不展示用户在 OpenDota 的全局历史战绩，除非后续单独做授权和产品说明。
- H5 第一版可不提供“我的”，小程序优先实现。

### 5.8 手机网页 H5 兜底页

目标：当小程序审核延迟、无法打开或需要外链分享时，用户仍能通过手机浏览器访问赛事数据。

内容：

- 首页、赛程、比赛记录、比赛详情。
- 选手主页、队伍主页。
- 标签云只读展示；H5 可播放本地应援反馈，但不写入点赞数。
- 分享标题、描述、封面图和复制链接。
- 小程序上线后提供“打开小程序”入口。

验收：

- 不登录也能查看公开赛程和比赛详情。
- 比赛详情 URL 可以直接分享给微信好友和浏览器用户。
- 与小程序共用 API 和核心展示字段。
- H5 页面在手机浏览器中不横向溢出。

## 6. Web Admin 关键页面

目标：赛事管理员在电脑浏览器中完成赛程维护、联赛配置、异常处理和必要的手动补录；小程序和 H5 只消费这些数据。

模块：

- 登录页：管理员账号密码登录，后续可增加微信扫码或二次验证。
- 工作台：首页展示待补录赛果、同步失败任务、近期赛程、数据概览。
- 赛季管理：创建赛季、设置默认赛季、配置 league_id。
- 赛事管理：创建赛事，配置阶段类型、阶段顺序、晋级规则和展示状态。
- 阶段管理：维护小组赛、瑞士轮、淘汰赛的参赛队、轮次、配对和 bracket。
- 队伍管理：队伍名、简称、Logo、成员。
- 选手管理：昵称、Dota 2 account_id、微信用户绑定状态、所属队伍。
- 赛程管理：创建比赛、设置时间、BO 类型、队伍、阶段。
- 赛果管理：录入比分、胜方、match_id、备注。
- 积分和晋级管理：查看后端自动排名、锁定阶段结果、手动修正排序或晋级队伍。
- 数据同步：配置 league_id、查看自动同步进度、失败原因，必要时手动重试或补录 match_id。
- 互动标签管理：查看、隐藏、恢复选手和队伍标签。
- 权限管理：授予或撤销管理员、队伍管理员。
- 审计日志：记录关键操作。

验收：

- 非管理员无法登录 Web Admin。
- 关键写操作必须落审计日志。
- 重复 match_id、重复赛程、非法比分有前后端校验。
- Web Admin 的列表、筛选、批量录入能力优先于视觉复杂度。

## 7. 核心业务流程

### 7.1 小程序用户登录

1. 用户填写必填展示昵称并点击小程序登录按钮。
2. 小程序调用 `wx.login` 获取 code，并将 code 与昵称一并上送。
3. 后端调用微信 `code2Session` 换取 openid 和 session_key。
4. 后端创建或更新用户，生成自定义登录态。
5. 小程序后续请求携带 token。
6. 用户可申请绑定 Dota 2 account_id，管理员审核或直接绑定白名单账号。

### 7.2 管理员创建赛事与阶段

1. 管理员登录 Web Admin。
2. 创建赛事并绑定赛季和 OpenDota league_id。
3. 添加阶段，选择阶段类型：普通小组赛、瑞士轮、淘汰赛。
4. 配置阶段规则：BO、参赛队、轮数、分组、晋级名额、排名规则。
5. 系统生成赛程、瑞士轮配对或淘汰赛 bracket 草稿。
6. 管理员检查并调整草稿后发布。
7. 用户端只展示已发布阶段和已发布 series。

### 7.3 管理员创建赛程

1. 管理员登录 Web Admin。
2. 选择赛季和阶段。
3. 选择赛事、阶段、轮次、双方队伍、BO 类型、计划时间。
4. 保存为“未开始”。
5. 比赛完成后录入比分、胜方和可选 match_id。
6. 如果提供 match_id，后端优先用该 match_id 同步并关联赛程；如果未提供，后端仍会通过 league_id 自动发现和匹配。

### 7.4 自动比赛数据同步

1. 管理员在 Web Admin 为赛季配置 OpenDota league_id 和同步频率。
2. 后端定时任务按 league_id 拉取联赛 match_id 列表。
3. 后端识别新 match_id，自动拉取 `/matches/{match_id}`。
4. 后端保存原始 JSON 和结构化字段，并尝试与已有赛程自动关联。
5. 如果缺少高级数据，后端自动按策略请求 `/request/{match_id}` 解析。
6. 后端定时轮询解析状态，解析完成后刷新比赛详情、Ban/Pick、曲线、聊天等高级数据。
7. 管理员只处理异常：同步失败、赛程无法自动关联、OpenDota 结果与人工赛果冲突、误关联 match_id。

### 7.5 管理员赛程与纠偏流程

1. 管理员创建赛程、队伍、选手和 BO 信息。
2. 管理员可选填 match_id；如果未填，后端仍会通过 league_id 自动发现新比赛。
3. 后端根据比赛时间、参赛队伍、match_id 等信息尝试关联赛程。
4. 自动关联失败时进入“待确认”列表，由管理员手动关联。
5. 人工赛果与 OpenDota 赛果冲突时进入“结果冲突”列表，由管理员确认展示结果。
6. 赛果确认后，后端重新计算小组赛/瑞士轮积分或淘汰赛晋级节点。
7. 如果自动排名或晋级结果需要修正，管理员可以手动覆盖并记录原因。

### 7.6 我的数据计算

1. 用户绑定 `dota_account_id`。
2. 后端按当前赛季和联赛过滤 `match_players`。
3. 聚合个人数据。
4. 返回给小程序，不调用 OpenDota 全局玩家统计接口作为主数据源。

### 7.7 H5 兜底访问

1. 管理员在 Web Admin 维护赛程、赛果、league_id 和异常数据。
2. 后端同步并缓存比赛数据。
3. H5 通过公开 API 读取赛程、比赛、选手和队伍数据。
4. 用户可直接打开或分享 H5 URL。
5. 需要登录互动时，H5 第一版引导用户打开小程序或等待后续 H5 登录能力。

## 8. 数据指标

比赛层：

- match_id、league_id、赛季、队伍、比分、胜负、时长、模式、开始时间、解析状态。
- tournament_id、stage_id、stage_type、round_id、group_id、bracket_node_id、BO 信息、发布状态。

赛事层：

- 阶段类型、小组、轮次、积分、排名、晋级线、瑞士轮 BYE、淘汰赛节点、手动排序原因。

玩家层：

- 英雄、等级、K/D/A、GPM、XPM、净值、正补、反补、参战率、伤害占比、英雄伤害、建筑伤害、治疗、承伤、装备、背包、中立物品、加点。

复盘层：

- picks_bans、gold_t、xp_t、objectives、teamfights、chat、lane、lane_role、kill_streaks、multi_kills。

管理层：

- league_id 配置、同步频率、赛程状态、人工比分、人工胜方、同步状态、同步错误、自动关联状态、操作日志。

互动层：

- 标签内容、目标类型、目标 ID、创建人、点赞数、当前用户是否点赞、审核状态、隐藏原因。

## 9. 非功能需求

性能：

- 首页和列表接口 P95 响应小于 500ms。
- 比赛详情接口允许较大 JSON，但 P95 小于 1200ms。
- OpenDota 外部请求必须异步化和缓存化，不阻塞普通用户访问。
- Web Admin 常用列表 P95 响应小于 800ms，支持分页、筛选和搜索。
- H5 首屏静态资源尽量控制在 500KB gzip 以内，公开详情页可被直接刷新访问。

可靠性：

- OpenDota 不可用时，展示缓存数据。
- 同步任务支持定时执行、自动重试、跳过失败、记录错误和管理员手动重试。
- 管理员误录 match_id 时支持解绑和重新同步。
- 云服务器必须支持自动重启、日志留存、数据库备份和基础告警。

安全：

- session_key 不下发到小程序。
- 所有管理员接口必须鉴权和鉴权角色。
- Web Admin 使用独立管理员登录态，不依赖小程序页面隐藏作为安全边界。
- 所有写操作记录操作者、时间、旧值和新值。
- 用户只能访问自己的“我的数据”，公开比赛数据除外。
- 标签添加和点赞必须登录；后端需要限制频率、去重和恶意刷赞，标签内容通过管理员审核把关。

合规：

- 小程序 request 域名必须配置 HTTPS。
- Web Admin 和 API 域名必须使用 HTTPS。
- H5 域名必须使用 HTTPS，并与 API 跨域配置一致。
- 用户资料绑定需要明确说明用途。
- 不采集不必要的个人敏感信息。

## 10. 成功标准

MVP 成功：

- 管理员能通过 Web Admin 完成一个赛季的队伍、选手、赛程、赛果维护。
- 管理员能创建并运营小组赛、瑞士轮和单败淘汰赛阶段。
- 小程序和 H5 能展示小组积分榜、瑞士轮轮次与积分榜、淘汰赛 bracket。
- 后端能在配置 league_id 后自动发现并同步新比赛。
- 后端能自动请求 OpenDota 解析，并在解析完成后更新高级数据。
- 用户能查看赛程和比赛详情。
- 小程序审核延迟时，用户仍可通过 H5 查看公开赛程和比赛详情。
- 选手登录后能看到自己的本联赛数据。
- 小程序登录用户能为选手和队伍添加标签，并为已有标签点赞。
- 至少 90% 已完赛比赛能通过 match_id 展示基础详情。
- 已解析比赛能展示 Ban/Pick、曲线、聊天和高级数据。

后续成功：

- 管理员每周维护时间下降。
- 选手个人数据页成为赛后分享入口。
- 比赛详情页具备足够强的社区传播性。
